# Запусти Киби Studio из одного промпта

Это инструкция для ИИ-помощника с **доступом к локальным файлам и терминалу на Mac**. Обычный облачный чат может объяснить шаги, но не запустит программу на компьютере сам. Если локальных инструментов нет, помоги пользователю открыть локальный проект в ChatGPT/Codex и повторить исходный промпт. Не сообщай об успешном запуске до проверки.

Киби Studio — личный локальный редактор приложений для одной платы: Киби DS-02. Он использует аккаунт ChatGPT/Codex, а не OpenAI API-ключ. На этом этапе не выбирай приложение за пользователя и не создавай прошивку: сначала открой редактор.

## 1. Получи согласованный снимок GitHub

Публичный источник: **https://github.com/ezggwp1216-pixel/kibi-studio**, основная ветка **main**. Репозиторий содержит инструкции, проверяемый комплект исходников/SDK в ZIP и внешний manifest. Файлы редактора находятся внутри комплекта, а не в корне GitHub.

Если эта инструкция уже прочитана из распакованной папки с `package.json`, `scripts/start.mjs` и `resources/`, пропусти повторное скачивание и переходи к проверке окружения.

Для новой установки:

Сначала проверь `python3 --version`. Если Python3 ещё недоступен, помоги установить официальный Python3 или Xcode Command Line Tools и повтори проверку. Не запускай helper до успешной проверки Python3.

1. Если пользователь, стартовый промпт или URL этой инструкции уже указал точный SHA, **сохрани этот SHA**: не заменяй его более новым коммитом ветки. Только если исходного SHA нет, один раз определи текущий коммит `main`: публичным GitHub API `GET https://api.github.com/repos/ezggwp1216-pixel/kibi-studio/commits/main` или `git ls-remote https://github.com/ezggwp1216-pixel/kibi-studio.git refs/heads/main`. Принимай только 40 строчных hex-символов. Не используй ключи/логины GitHub и не копируй настройки Git из других проектов.
2. Зафиксируй этот SHA и перечитай `START_HERE.md` по адресу `https://raw.githubusercontent.com/ezggwp1216-pixel/kibi-studio/<SHA>/START_HERE.md`. Дальше все файлы загружай **из того же SHA**, без смешивания версий `main`.
3. Загрузи `release.json` и `bootstrap.py` с того же префикса. Проверь SHA-256 загруженного helper по полю `bootstrapSha256` из `release.json`; при отсутствии поля или несовпадении остановись. Сначала сохрани файл, затем выполни его — не используй `curl | sh` и не запускай ответ сервера как команду.
4. Выбери существующую рабочую папку и **новую, ещё не существующую** подпапку для Studio. Например, `KibiStudio-<первые 8 символов SHA>`. Не удаляй и не перезаписывай ранее начатый проект. Если имя занято, выбери новое.
5. Запусти сохранённый helper системным Python3, передав точный SHA и абсолютный новый путь:

```sh
python3 /абсолютный/путь/bootstrap.py --commit <SHA> --destination /абсолютный/путь/к/новой/КибиStudio
```

Пути с пробелами передавай отдельными аргументами или корректно цитируй. Helper сам загрузит `release.json`, `kibi-studio-local.manifest.json` и `kibi-studio-local.zip` из того же коммита; проверит размеры/SHA-256 каждого файла, пути и типы записей; распакует только в новую папку. Он не устанавливает программы, не запускает скачанный код, не читает авторизацию и не обращается к USB. Проверь его успешный exit code и поле `projectPath`, затем продолжай в этой папке.

## 2. Проверь инструменты на Mac

Прочитай локальные `AGENTS.md`, `README.md` и `docs/development-contract.md`. Не открывай `.studio/private`, `auth.json`, резервные копии платы или личные BIN.

Нужны:

| Компонент | Требование |
|---|---|
| macOS | Текущий выпуск использует штатную macOS-изоляцию native-процессов |
| Node | Версия 22.12 или новее |
| Codex CLI | Команда `codex`, поддерживающая текущий app-server; вход через ChatGPT |
| Arduino IDE | Arduino CLI 1.5.1 внутри стандартной установки Arduino IDE |
| ESP32 tools | Core 3.3.12 и esp-x32/2601 в штатном Arduino15 |
| Xcode Command Line Tools | `clang++`, macOS SDK и `python3` |

Точный SDK Киби IDF 5.5.5, шрифты, библиотеки и лицензии уже входят в комплект. Не заменяй их случайной ESP32-платой, не меняй пины/разметку памяти и не устанавливай произвольные библиотеки.

Проверь `node --version`, наличие `codex`, `xcode-select -p` и выполни `npm run doctor`. Если инструмента нет, назови конкретно недостающий компонент, возьми способ установки из официальной документации поставщика и помоги завершить установку. Не меняй глобальную конфигурацию Codex, не ослабляй изоляцию и не обещай, что этот helper уже установил отсутствующие программы. Для компиляции `doctor` должен вернуть `ready:true`; простая установка Node ещё не означает готовый компилятор.

## 3. Подключи ChatGPT

Выполни `codex login status`. Если вход уже действителен через ChatGPT, используй его. При отсутствии входа запусти `codex login`: пользователь завершает официальный вход в открывшемся браузере. Не проси пароль, токен или API-ключ в чате; не читай и не копируй `auth.json`. Затем снова проверь статус.

История Studio сохраняется отдельно от облачного ChatGPT Project. Этот вариант предназначен для личной локальной работы; не публикуй локальный процесс авторизации на VPS. Официальный порядок входа: https://learn.chatgpt.com/docs/auth?surface=cli.

## 4. Запусти редактор и проверь результат

В папке `projectPath` запусти:

```sh
node scripts/start.mjs --open
```

Оставь процесс работать и открой `http://127.0.0.1:4387` в Chrome/Edge. Сервер должен слушать только localhost. Если порт занят, проверь процесс и его рабочую папку: если это нужная Studio, используй существующую; посторонний процесс не останавливай. Для отдельной копии можно выбрать свободный порт через `KIBI_STUDIO_PORT`, затем открыть именно его адрес.

Проверь на странице: название проекта, статус «ChatGPT подключён», настоящий экран Киби и доступное поле чата. При ошибке покажи конкретное состояние и продолжи исправление; не заменяй настоящий чат демонстрационными ответами. Разверни предпросмотр, проверь нажатия/свайпы и кнопку «Проверить». Это проверка общего renderer/state/input; она не подтверждает работу радио, микрофона или питания на физическом устройстве.

Сообщи пользователю адрес и папку проекта. Спроси, что он хочет создать для Киби. Плата для запуска редактора не требуется; не начинай сборку или USB-запись автоматически.

## Что происходит после запуска

ИИ получает контракт Киби и помогает пройти путь «идея → варианты функций/дизайна → интерактивный макет → согласование → код». `app_view.h` — отрисовка, `app_core.h` — состояние/управление, `app_feature.h` — модульная логика. Защищённые адаптеры и драйверы сохраняются. Макет и прошивка используют общий C++ код и Source Sans3.

Wi-Fi/API-значения пользователь вводит только в «Настройках» и только по необходимости выбранной функции. В контекст ИИ и экспорт они не входят. Сборку пользователь запускает отдельно; подключение USB, согласование конкретного бинарника и запись — отдельные явные действия. Локальная успешная сборка не заменяет физическую проверку платы.
