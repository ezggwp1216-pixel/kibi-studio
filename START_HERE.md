# Киби Studio: установка с нуля

Откройте новый локальный проект Codex с терминалом и передайте ему bootstrap-prompt.txt.
Для публичного репозитория GitHub-вход не нужен. Нужны Mac, интернет и около 2 ГБ
свободного места. Установщик сам скачивает закреплённые Node и Codex; при отсутствии
Chrome/Edge он предлагает подписанный Chrome. Arduino IDE, Python, Homebrew и Xcode
пользователю не нужны. Исходники и история проекта хранятся локально, компиляция
предпросмотра и прошивки выполняется сервером Киби, USB-загрузка — локальным браузером.

Инструкция помощнику:

1. Если полный SHA уже указан пользователем или ссылкой, сохраните его. Иначе один
   раз получите SHA main через публичный
   `GET https://api.github.com/repos/ezggwp1216-pixel/kibi-studio/commits/main`.
   Принимайте ровно 40 строчных hex-символов. Все последующие файлы берите из этого
   же коммита; не разрешайте main повторно посреди установки.
2. Загрузите START_HERE.md, release.json и bootstrap.sh из raw.githubusercontent.com/
   ezggwp1216-pixel/kibi-studio/<SHA>/. Проверьте SHA-256 bootstrap.sh по
   bootstrapShellSha256 до запуска. Не используйте curl | sh.
3. Выберите новую абсолютную папку под текущим рабочим каталогом. Запустите сохранённый
   проверенный bootstrap.sh с --commit <SHA> --destination '<новая папка>'. Ничего не
   устанавливайте поверх существующей Studio. --install-only не выполняет вход и запуск.
4. Пользователь сам завершает официальный вход ChatGPT в браузере. Пароли, OTP, API-ключи
   и коды подключения не вводятся в чат; auth.json и личные настройки не открываются.
5. Откройте выданный локальный адрес в Chrome/Edge. При занятом порте выберите свободный
   через KIBI_STUDIO_PORT; чужие процессы не останавливайте. Проверьте настоящее сообщение,
   текущий кадр и касания. Наличие Node само по себе не доказывает работу редактора.
6. Полный комплект содержит согласованные программы, SDK, инструкции, клиент
   Xiaozhi и инструменты серверных модулей. Дополнительный старый overlay не нужен.
   Для проверки в чате Studio вызовите только `kibi_project_context`: прочитайте сведения о плате,
   SDK и список `platform.deviceModules.modules` из его ответа. Отдельного инструмента
   каталога нет. Статусы доступности, совместимости и добавления Xiaozhi берите только
   из фактических данных. Для голоса нужен профиль «Киби с динамиком»; сообщите, что
   реально выбрано, а при отсутствии данных — «неизвестно». Не меняйте профиль и не
   вызывайте `kibi_enable_module` в ходе проверки запуска. Наличие SDK не доказывает
   связь с сервером, микрофон или звук на плате.

Необязательная проверка кабинета выполняется отдельно, по просьбе пользователя:
`kibi_account_status`, затем при подключённом кабинете `kibi_server_modules` и
`kibi_server_guide({topic:"server-modules"})`. Для списка собственных устройств есть
`kibi_account_devices`. Это чтение, без publish/bind/rollback, активации, провайдера
или выполнения модуля. Если кабинет отключён, подключение истекло, нет прав или
сервер не поддерживает API, покажите точный блокер. Live-возможности в таком случае
не проверены; не подставляйте успешный статус. Не запрашивайте секреты в чате.

Новый проект: опишите идею, согласуйте макет и управление, нажмите «Проект готов».
Studio проверит реализацию, после готовности покажет «Собрать прошивку».
Пользователь запускает сборку этой кнопкой; проверка запуска сама её не запускает.
Wi-Fi/API заполняются только по необходимости в закрытых настройках. Установка на плату
потребует отдельного USB-подключения, проверенного плана и подтверждения записи.

Аккаунт Киби не нужен для автономного проекта. Для сервера и своего Xiaozhi зарегистрируйтесь
на https://sldvkibi.ru/server/, получите код подключения Studio и введите его в форму
«Аккаунт». После прошивки отдельно привяжите код самой платы. Затем в своём кабинете
подключите собственный Xiaozhi, выберите Киби, сохраните характер и перенесите роль в
официальную консоль Xiaozhi. Подробности: docs/STUDIO_CONNECTION.md внутри комплекта.
Бесплатный Open Source режим Xiaozhi применяется по его соглашению, не обещает постоянный
бесплатный или коммерческий доступ. Вход и соглашение подтверждает сам пользователь.

Для **своего серверного модуля** в кабинете нажмите «Подключить Studio», отметьте
«Разрешить этой Studio публиковать серверные модули и назначать их моим Киби»,
получите новый код и введите его только в форму «Аккаунт» Studio. Старые подключения
не получают новые права автоматически. Этот код отличается от короткого кода платы.

Попросите ИИ создать модуль вместе с приложением. Сначала он читает
`kibi_server_guide({topic:"server-modules"})`, проверяет свои устройства,
runtime/media и текущие привязки. После вашей просьбы он может опубликовать пакет
через `kibi_publish_server_module({packageText})`, прочитать привязки через
`kibi_device_modules` и назначить версию через `kibi_bind_server_module` с актуальной
ревизией. SHA-256 вычисляет Studio; вручную считать хеш не требуется.

Те же действия доступны в «Серверные модули»: загрузить `.kibiplugin` →
«Опубликовать версию» → выбрать свою Киби, версию и публичные настройки →
«Модуль включён для этого устройства» → «Сохранить привязку». Для выключения снимите
флаг и сохраните; для обновления опубликуйте новую версию и выберите её. Для отката
укажите прежнюю ревизию и нажмите «Восстановить» либо попросите ИИ использовать
`kibi_rollback_server_module`. Вернутся версия, настройки и включение как новая
ревизия; прошивка не откатывается. При конфликте сначала обновите список.

Модуль вызывается приложением Киби, а не автоматически по публикации или включению.
JavaScript работает отдельно от HTTP-сервера, без произвольной сети и доступа к
секретам. Пароль кабинета, токен Studio и ключи серверных интеграций не входят в
пакет, обычные настройки или прошивку. Их вводят только в закрытых формах.
Приложение использует отдельный токен своей привязанной Киби; получает и сохраняет
его само устройство. Секреты пользовательских модулей и расписания не реализованы.

Фактические runtime/media статусы видны в окне модулей. Ошибку `/invoke` получает
приложение Киби: покажите понятный текст, фиксированный код, «Повторить» и
«Остановить». Например, `plugin_runtime_unavailable`, `plugin_runtime_timeout`,
`plugin_runtime_failed`, `plugin_media_unavailable`. Истории вызовов в этом окне
нет; «Диагностика Киби» относится к голосу. Публикация, привязка и успешная сборка
не подтверждают работающий Docker/media runtime, настоящий YouTube-кадр, плавное
видео, звук или физическую Киби. Для этого нужны отдельные реальные проверки.
Подробнее: [серверные модули](https://sldvkibi.ru/server/docs/SERVER_MODULES.md).

Повторный запуск — «Запустить Киби Studio.command» в папке установки. Не удаляйте .studio
или проекты при обновлении. Установка/проверки программы не заменяют отдельный тест платы.

## Фото для приложения

Нажмите «Добавить фото» в чате Studio, отправьте картинку и напишите, как её использовать:
например, «Поставь это фото фоном под крупные цифры». Уже отправленное фото можно использовать
из того же проекта. Публиковать картинку в интернете или присылать HTTPS-ссылку не нужно.
Studio сама подготовит ресурс для макета и прошивки; ИИ согласует его положение и читаемость
элементов. Добавление фото само не запускает сборку и не прошивает устройство.
Подробнее: [фото из чата](studio-integration/docs/CHAT_PHOTOS.md).
