# Свои серверные модули Киби

Studio помогает создать обработчик, опубликовать его в вашем кабинете и
назначить своей Киби. Публикация сохраняет версию; обработчик запускается
только по запросу приложения устройства и при доступном исполнителе.

Возможности исполнителя определяются вашим сервером, а не наличием этой
инструкции. Для установки используйте полный Git-коммит выбранного выпуска;
работу приложения на физической Киби проверяйте отдельно.

## От Studio до первого вызова

1. Получите **полный выпуск Studio с серверными модулями** из
   [публичного GitHub](https://github.com/ezggwp1216-pixel/kibi-studio) по точному
   коммиту и инструкции выбранного релиза. Установите в новую папку штатным
   проверяемым bootstrap и проверьте инструменты через чат Studio.
   Для совместимой существующей Studio есть отдельное
   [обновление](SERVER_MODULES_DEPLOY.md#комплекты-studio); личные проекты не заменяйте.
2. Войдите в свой кабинет сервера. Нажмите «Подключить Studio», отметьте
   «Серверные модули» и получите новый одноразовый код. Вставьте его только
   в форму «Аккаунт» Studio. Прежние подключения сохраняют прежние права.
3. Попросите ИИ создать приложение и серверный модуль. Например:
   «Сделай для моей Киби беззвучный просмотр YouTube по ID видео. Проверь
   возможности сервера, создай модуль и приложение с ошибкой, повтором и
   остановкой; опубликуй версию и назначь моей Киби». ИИ сначала проверяет
   подключение, список ваших устройств, модули и доступность runtime/media.
4. ИИ создаёт публичный `.kibiplugin` v2 и публикует его штатным инструментом;
   Studio сама вычисляет SHA-256. Вручную это доступно в «Серверные модули →
   Загрузить .kibiplugin → Опубликовать версию». Ключи и пароли вводите только
   в закрытых формах нужного сервиса, никогда в чате, пакете или обычных настройках.
   Секреты для пользовательских v2-модулей пока не поддерживаются.
5. В «Серверные модули» выберите свою привязанную Киби, модуль и версию,
   проверьте публичные настройки, отметьте «Модуль включён для этого устройства»
   и нажмите «Сохранить привязку». Если Киби отсутствует, сначала подтвердите
   её короткий код через штатную форму привязки. Назначение не устанавливает приложение.
6. Проверьте макет и управление, разрешите реализацию через «Проект готов».
   Studio подготовит сборку; установку по USB подтвердите отдельно для своей
   платы. Приложение вызывает модуль с токеном устройства. Токен Studio в
   прошивку не передаётся. Первый реальный вызов выполняйте явно из приложения.

Те же операции с пакетами и привязками доступны в разделе «Модули» своего
кабинета. Само включение не создаёт фоновые задачи или расписание.

## Остановить, обновить, вернуть

- **Выключить:** снимите «Модуль включён для этого устройства» и сохраните
  привязку. Текущий запрос отменяется, поздний результат не применяется.
- **Включить:** выберите нужную версию, проверьте настройки, поставьте флаг
  и сохраните. Запуск начнётся со следующего запроса приложения.
- **Обновить:** попросите ИИ опубликовать новую версию, затем выберите её для
  этой Киби и сохраните. Содержимое уже опубликованной версии не заменяется.
- **Откатить:** в «Вернуть предыдущую ревизию привязки» укажите прежний номер
  и нажмите «Восстановить». Вернутся её версия, настройки и состояние
  включения как новая ревизия. Это не откат прошивки платы.

При конфликте обновите список, проверьте текущую версию и ревизию, затем
повторите нужное действие. Не перезаписывайте изменения вслепую.

## Как увидеть настоящую ошибку

В окне модулей «Изолированный исполнитель» и «Видео YouTube» показывают
возможности выбранного сервера. «Не настроен» означает отсутствие настройки;
«Доступность не подтверждена» — что успешный запуск сейчас не подтверждён. Публикация и настройка привязок могут
оставаться доступными; их ошибки показаны в том же окне.

Ошибка самого вызова приходит **приложению Киби** из `/invoke` как
`{ok:false,code:"…"}`. Попросите ИИ показывать понятный текст, фиксированный
код и кнопку «Повторить»; при остановке прекратить запросы. Например,
`plugin_runtime_unavailable` — недоступен исполнитель,
`plugin_runtime_timeout` — обработчик не уложился в срок,
`plugin_runtime_failed` — обработчик завершился с ошибкой,
`plugin_media_unavailable` — недоступен видеообработчик или выбранное видео.
`plugin_media_provider_restricted` (HTTP 424) — источник YouTube требует
подтверждения доступа и не предоставил поток. Это не ошибка Wi-Fi Киби или
компилятора; не передавайте cookies, пароль YouTube или токены в чат/пакет.
Код не раскрывает внутренний текст исключения или вывод worker. Для помощи
сообщите код, версию модуля и действие, без ключей и токенов.

Истории вызовов в окне модулей пока нет. «Диагностика Киби» в окне «Аккаунт»
относится к голосу и не заменяет результат вызова модуля. Уведомление в очереди
не доказывает показ, успешный кадр не доказывает воспроизведение на плате.

## Что умеет этот выпуск

Исполняемые пакеты используют `manifestVersion:2`, `sdkVersion:"1.1"`.
Реализованы обработчик запроса и разрешённые результаты: данные, постановка
уведомлений своей Киби (`notifications:create`) и один кадр YouTube
(`media:youtube-frame`). Имена event/message-обработчиков поддержаны форматом,
но автоматической подписки на события или сообщения нет: вызов делает приложение.
Расписания ещё не реализованы.

JavaScript работает отдельно от HTTP-сервиса, в контейнере без сети, секретов
и доступа к данным кабинета. Произвольные внешние API из исходника недоступны.
YouTube получает отдельный доверенный обработчик по ID из 11 символов, без
произвольного URL. Пример — [youtube-live.kibiplugin](../examples/server-plugin/youtube-live.kibiplugin):
без звука, кадр 240×296 RGB565LE, `contain` с полями или `cover` с обрезкой.
Приложение запрашивает кадры последовательно. Плавность и задержка требуют
измерений; это не непрерывный видеопоток. Подробности: [YOUTUBE_MODULE.md](YOUTUBE_MODULE.md).

## Контракт для разработчика

Перед реализацией ИИ читает `kibi_server_guide({topic:"server-modules"})`.
Он использует реальные инструменты `kibi_account_status`, `kibi_account_devices`,
`kibi_server_modules`, `kibi_publish_server_module({packageText})`,
`kibi_device_modules`, `kibi_bind_server_module`, `kibi_rollback_server_module`.
Перед изменением он читает текущую привязку и передаёт `expectedRevision`;
для первой привязки — 0. Пользователь не вычисляет хеш вручную.

| Маршрут | Действие |
| --- | --- |
| `GET /api/studio/plugins` | Собственные версии и фактические runtime/media capabilities |
| `POST /api/studio/plugins` | `{packageText,sha256}` — неизменяемая версия |
| `GET /api/studio/devices/:deviceId/plugins` | Привязки своей Киби |
| `POST /api/studio/devices/:deviceId/plugins/:pluginId` | `{version,expectedRevision,enabled,settings}` |
| `POST …/:pluginId/rollback` | `{toRevision,expectedRevision}` |
| `POST /api/device/plugins/:pluginId/invoke` | Токен устройства и `{input}` |

Кабинет использует соответствующие маршруты без `/studio`, с cookie, Origin
и CSRF. Владелец определяется сессией или bearer, никогда JSON-полем.
Новые `plugins.read`, `plugins.publish`, `plugins.bind` выдаются только явно
разрешённому новому подключению с `X-Kibi-Studio-Protocol: plugins-v1`.

Старый SDK-валидатор v1 и `/api/sdk` остаются структурной проверкой без запуска;
его `execution:false` не описывает доступность отдельного v2 runtime.
Пакет ограничен 128 КиБ, source — 64 КиБ, ввод/вывод — 64 КиБ; handler —
5 секунд. Допуск — четыре полных вызова на HTTP-процесс и один на
кабинет/устройство/модуль. Неопределённая очистка контейнера отключает
исполнитель до проверенного восстановления оператором.

Кадр: 142080 байт, `application/octet-stream`, `X-Width:240`, `X-Height:296`,
`X-Pixel-Format:rgb565le`, `X-Content-SHA256`, `X-Binding-Revision`.
Неполный кадр или неверный хеш не показывается. Отзыв устройства и изменение
привязки отменяют прежнюю работу. Установка и восстановление runtime:
[SERVER_MODULES_DEPLOY.md](SERVER_MODULES_DEPLOY.md).
