# Фото из чата в приложении Киби

Фото, отправленное в чат текущего проекта Studio, уже доступно модели как
визуальный JPEG-вход. Анализ картинки и добавление её в приложение — отдельные
операции. Чтобы использовать это же фото как фон или другой статический ресурс,
не нужна публичная ссылка, повторная загрузка или новый ключ сервиса.

## Выбор уже отправленного фото

ИИ читает `kibi_project_context`. В `platform.chatAttachments` находятся только
разрешённые фото текущего проекта: непрозрачный `id`, номер `index`, MIME, размеры
и SHA-256. `platform.attachmentImport.supported` сообщает, подключён ли локальный
импорт в этом host; наличие описания фото само по себе не подтверждает импорт.
`platform.attachmentImport.network` равно `false`.

В сообщении `CURRENT USER PHOTO ATTACHMENTS` Studio отдельно сопоставляет порядок
изображений в текущем пользовательском вводе с их ID. Если отправлено несколько
фото, ИИ выбирает ID нужной картинки по этому порядку и данным контекста.
Не следует придумывать ID, URL или путь к файлу. Старое вложение выбирается только
из фактически доступного контекста текущего проекта.

Для локального вложения используется ровно один аргумент:

```js
kibi_import_asset({attachmentId: idИзКонтекстаТекущегоПроекта})
```

Прежний импорт публичных ресурсов сохранён как отдельный вариант:
`kibi_import_asset({url})` или `kibi_import_asset({url,recipe})`. `attachmentId`
нельзя смешивать с `url` или `recipe`. Для фото, уже отправленного в чат,
публичный HTTPS-адрес не требуется.

## Локальная обработка

Studio разрешает ID через собственное хранилище вложений текущего проекта.
Модель не выбирает файловый путь и не получает право читать другие проекты,
личные настройки или файлы авторизации. Смена проекта, отмена действия и отзыв
доступа повторно проверяются до чтения и перед добавлением ресурса.

Поддерживаются уже загруженные JPEG, PNG и WebP в пределах проверок загрузки.
На Mac JPEG/WebP преобразует встроенный `/usr/bin/sips`; PNG обрабатывается
штатным локальным растеризатором. Дополнительные программы, npm-пакеты и сетевой
конвертер устанавливать не нужно. Временные файлы принадлежат только операции,
ограничены по размеру и удаляются после неё. Эта операция не обращается к API
кабинета, медиапровайдеру или публичной ссылке.

Результат добавляется через существующий защищённый механизм в банк ресурсов
проекта. Инструмент возвращает точный API RGB565/alpha, включая `ReadPixel` и
`DecodeRow`, для предпросмотра и прошивки. ИИ должен использовать этот API,
сохранять читаемость текста и обрезку изображения по экрану. Писать собственный
JPEG/PNG/WebP-декодер в приложении не требуется. Одно фото не становится набором
кадров анимации лица автоматически.

## Проверка результата

Можно попросить: «Используй первое фото из этого сообщения как фон. Прочитай
контекст проекта, импортируй соответствующий attachmentId и покажи результат
в макете, сохранив читаемый текст».

Успешный импорт не подтверждает, что фон уже виден. Нужна проверка текущего
нативного результата и макета. Импорт не запускает сборку прошивки, модельный
запрос или запись по USB. Сборка и установка остаются отдельными действиями
существующего процесса Studio.

Если импорт недоступен, нужно назвать фактический отсутствующий host capability
или фиксированный код ошибки. Например, `ATTACHMENT_CONVERTER_UNAVAILABLE`
означает отсутствие поддерживаемого локального конвертера,
`ATTACHMENT_NOT_ALLOWED` — отсутствие доступа к этому ID,
`ATTACHMENT_PROJECT_CHANGED` — смену проекта,
`ATTACHMENT_CONVERSION_FAILED` — неудачное преобразование.
Не следует сообщать об установленной картинке после ошибки или просить публичную
ссылку как обязательный шаг для уже отправленного фото.
