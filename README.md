# Киби Studio

Полная локальная мастерская приложений для Киби: свой ChatGPT, макет, исходники,
серверная компиляция и подтверждаемая USB-установка. Комплект 0.3.1 включает
программы платформы r3, аппаратный SDK, готовый клиент Xiaozhi и инструменты
собственных серверных модулей. Доступность исполнителя проверяется на выбранном
сервере отдельно.

Начните с [START_HERE.md](START_HERE.md): передайте [стартовый промпт](bootstrap-prompt.txt)
локальному Codex с терминалом. Установщик проверит файлы по закреплённому commit и
контрольным суммам и загрузит необходимую среду в новую папку. Пользователь сам
завершает официальный вход ChatGPT. Обычный веб-чат без локальных инструментов
не может установить редактор на компьютер.

Новый проект → идея → согласование макета и управления → «Проект готов» →
проверка кода → сборка сервером → подтверждённая установка через USB.
Для локального чата не нужен API-ключ OpenAI, для автономного приложения — аккаунт Киби.
Wi-Fi и ключи сервиса вводятся в предназначенных формах только по необходимости.

После запуска ИИ проверяет `kibi_project_context`: сведения о плате, SDK и
`platform.deviceModules.modules` приходят вместе с данными проекта. Отдельного
инструмента каталога нет. Неизвестный статус нельзя заменять обещанием работающей
связи. Для голоса нужен профиль «Киби с динамиком»; его фактический выбор, установку
модуля, сборку и звук на устройстве проверяют отдельно.

Для своего Xiaozhi и серверных функций подключите личный кабинет на
https://sldvkibi.ru/server/ . Studio, физическая плата и Xiaozhi связываются разными
кодами. Сохранённая роль переносится в своего агента Xiaozhi вручную при первой
настройке и после изменения характера;
контекст и разрешённые действия обслуживает сервер. Условия Xiaozhi принимаются
пользователем отдельно.

Для серверных модулей создайте в кабинете **новый код «Подключить Studio»** с
разрешением «Разрешить этой Studio публиковать серверные модули и назначать их
моим Киби» и вставьте его только в форму «Аккаунт» Studio. Старые подключения
сохраняют прежние права. Необязательная проверка через `kibi_account_status`,
`kibi_server_modules` и `kibi_server_guide({topic:"server-modules"})` только читает
состояние. Отключённый кабинет означает, что live-возможности сервера не проверены.

Опишите ИИ модуль вместе с приложением, затем явно попросите опубликовать версию
и назначить своей привязанной Киби. В «Серверные модули» можно загрузить публичный
`.kibiplugin` v2, опубликовать, выбрать устройство/версию, включить и сохранить
привязку. Studio сама вычисляет SHA-256. Для обновления публикуют новую версию,
для остановки снимают флаг включения, для отката восстанавливают прежнюю ревизию
привязки. Обработчик вызывает приложение: публикация и включение не запускают
автоматическую фоновую задачу. Точный контракт —
[серверные модули](https://sldvkibi.ru/server/docs/SERVER_MODULES.md).

Пароль кабинета, код подключения, токен Studio и ключи серверных интеграций не
входят в пакет или прошивку. Они вводятся только в закрытых формах; JavaScript
модуля не получает произвольную сеть или секреты. Приложение использует отдельный
токен своей привязанной Киби, который получает и сохраняет само устройство.
Расписания пока не реализованы. Реальные кадры YouTube, Docker/media runtime и
работу приложения на плате нельзя считать проверенными по пакету или сборке.
Ошибка вызова приходит приложению Киби фиксированным кодом; ИИ должен показать
её, повтор и остановку, а доступность runtime/media — взять из фактического ответа.

[Полный комплект](kibi-studio-local.zip), [release](release.json),
[manifest](kibi-studio-local.manifest.json) и [runtime-lock](runtime-lock.json).
Источники, история и настройки остаются локально; сервер получает необходимые
исходники и параметры для компиляции. В поставке нет личных данных и прошивок.
Проверки программы и компиляция не заменяют отдельную проверку звука, тача и сети на Киби.
