# Запуск своего Kibi Server

Самый короткий путь: передайте ИИ содержимое [bootstrap-prompt.txt](bootstrap-prompt.txt). Он должен проверить компьютер, подготовить запуск и показать результаты проверок. Пароль панели, токен устройства и ключи интеграций остаются у вас; не вставляйте их в чат.

Используйте помощника с доступом к терминалу на целевом компьютере или сервере. Текстовый чат без инструментов сможет дать инструкции; команды на вашей машине ему недоступны.

## Получите исходники

Исходники: [папка server в ветке codex/kibi-server](https://github.com/ezggwp1216-pixel/kibi-studio/tree/codex/kibi-server/server) публичного репозитория Kibi Studio. Сам сервер не требует запуска Studio. Клонирование также получает остальные файлы общего репозитория; команды запускайте именно из `server/`. Для первой установки в отдельный новый каталог:

```sh
git clone --branch codex/kibi-server --depth 1 https://github.com/ezggwp1216-pixel/kibi-studio.git
cd kibi-studio/server
git rev-parse HEAD
```

Сверьте полный идентификатор коммита с выбранной вами версией на GitHub перед запуском кода. Помощник должен записать эту версию в отчёт; одного имени ветки недостаточно. Не копируйте поверх существующей установки и не берите файлы из чужих проектов Studio.

## Локальный запуск

Установите Node.js 24 или новее из [официального источника](https://nodejs.org/en/download), если его ещё нет. В каталоге проекта:

```sh
node --version
npm run init
npm test
npm start
```

Откройте [http://127.0.0.1:4391](http://127.0.0.1:4391), именно `127.0.0.1`, не `localhost`: защита Origin проверяет точное совпадение. Остановка — Ctrl+C. После повторного `npm start` сохранённые устройства и события останутся.

Скрипт создаёт `.data` с правами `0700`, а случайный пароль `.data/admin-password` — с правами `0600`. Повторный запуск сохраняет пароль и содержимое. Каталог должен принадлежать пользователю запуска; ссылки и файлы с несколькими жёсткими ссылками отвергаются. Путь к каталогу и его родителям должен быть без символических ссылок; на macOS используйте физический путь (`pwd -P`). Инициализируйте при остановленном сервере. При пропавшем пароле в непустом каталоге скрипт остановится: восстановите полный исходный комплект данных, не удаляйте ключи.

**Только вы, в своём локальном терминале, без записи экрана/вывода в чат**, можете посмотреть пароль:

```sh
cat .data/admin-password
```

Помощник не должен запускать эту команду ради показа результата в чате. Введите пароль в форму панели. Не публикуйте `.data`, резервные копии, `.env`, токены или журналы с секретами.

## Docker Compose

Нужен Docker Engine/Desktop с Compose v2. Если они отсутствуют, помощник проверяет подходящий официальный способ и устанавливает необходимые компоненты в рамках уже разрешённого развёртывания. Дополнительное решение нужно только для новых расходов, удаления данных или ещё не согласованных существенных изменений безопасности. Используйте [официальную установку Docker для вашей ОС](https://docs.docker.com/engine/install/); не запускайте удалённые скрипты через pipe в shell. Эти инструкции не требуют SSH, root-скрипта установки, доступа приложения к `docker.sock` или автоматической смены firewall.

Команды ниже выполняются **обычным пользователем**, имеющим право работать с Docker. Не используйте UID 0. Приложение внутри контейнера запускается с вашим UID/GID, чтобы читать файл `0600` без ослабления прав:

```sh
export KIBI_UID="$(id -u)"
export KIBI_GID="$(id -g)"
test "$KIBI_UID" -ne 0
docker compose version
```

Если проверка UID завершилась ошибкой, остановитесь и выберите обычную учётную запись. Запоминайте эти два несекретных значения для каждого запуска Compose: при другом UID существующие данные будут недоступны. Можно сохранить только эти значения в приватном `.env` через свой редактор; это не место для API-ключей.

Первый запуск, если на компьютере есть Node 24:

```sh
npm run init
docker compose build
docker compose up -d
```

Вариант **без Node на хосте**: сначала убедитесь, что `.data` отсутствует или является вашим обычным каталогом без ссылок. Для новой установки создайте его, затем выполните инициализацию тем же непривилегированным контейнером:

```sh
mkdir -m 700 .data
docker compose build
docker compose run --rm --no-deps kibi node scripts/init.mjs
docker compose up -d
```

Для существующей `.data` не повторяйте `mkdir`; проверьте владельца и запустите `init` без пересоздания каталога. Bind mount специально не создаётся Docker автоматически, чтобы каталог не оказался принадлежащим root. Не исправляйте проблему командой `chmod 777` и не запускайте сервер от root. Данные пишутся только в `.data`; корневая файловая система контейнера доступна лишь для чтения. Не запускайте одновременно Node-сервер и Compose на одной `.data`.

```sh
docker compose ps
curl --fail http://127.0.0.1:4391/api/health
```

Ожидается HTTP 200 с `ok:true` и именем `kibi-server`; контейнер должен перейти в `healthy`. Образ собирается из исходников, Node-образ закреплён по digest. Порт `4391` опубликован только на loopback. После перезагрузки хоста Docker должен быть настроен на запуск его службой; Compose использует `unless-stopped`.

### Публичный HTTPS

Нужен ваш домен с A-записью на этот сервер; если есть AAAA, она тоже должна вести на работающий IPv6 этого сервера. Внешние TCP 80 и 443 должны быть свободны и доступны, исходящий HTTPS нужен для сертификатов и выбранных интеграций. Помощник выполняет уже согласованные изменения DNS/firewall и настройку службы; если публичный доступ ещё не согласован, сначала уточняет это решение. Если уже есть reverse proxy, согласуйте схему с ним, не запускайте второй слушатель тех же портов.

Вместо `kibi.example.com` укажите **свой DNS hostname без схемы, порта и пути**:

```sh
export KIBI_DOMAIN=kibi.example.com
docker compose -f compose.yaml -f compose.https.yaml config --quiet
docker compose -f compose.yaml -f compose.https.yaml up -d
```

HTTPS-вариант автоматически задаёт приложению точный Origin `https://$KIBI_DOMAIN`, а Caddy получает сертификат и перенаправляет HTTP на HTTPS. Входите по этому HTTPS-адресу; cookie становится Secure. HTTP-порт приложения остаётся доступен только локально для проверки здоровья, браузерный вход через него при HTTPS Origin будет отклонён.

```sh
curl --fail "https://$KIBI_DOMAIN/api/health"
```

Не обходите ошибки сертификата через `-k`. Сохраните `KIBI_DOMAIN` и UID/GID для последующих запусков. Всегда используйте оба файла Compose для этой установки, включая `stop`, `restart` и обновление. Caddy работает без root на внутренних портах 8080/8443; сертификаты сохраняются в именованных томах `caddy_data`/`caddy_config`. Для воспроизводимых обновлений также проверяйте и закрепляйте выбранный образ Caddy по digest перед развёртыванием. Подробнее: [автоматический HTTPS](https://caddyserver.com/docs/automatic-https).

## Проверьте свой экземпляр

1. Войдите в панель. Новая установка должна показывать пустой список устройств и событий, реальные статусы модулей.
2. Создайте устройство. Сохраните показанный один раз токен у себя. Отправьте с ним `POST /api/device/events`, затем повторите тот же `eventId`: появится одно событие. Второе устройство имеет свой токен и свою дедупликацию.
3. Отправьте устройству сообщение из панели. Получите его через `GET /api/device/messages`, подтвердите `POST /api/device/ack`: подтверждённое сообщение исчезнет из очереди.
4. Перезапустите сервер. Список устройств и недавние события должны сохраниться. Удалите тестовое устройство и убедитесь, что старый токен больше не работает.
5. Если нужен текстовый ИИ: введите свой OpenAI API-ключ в панели, выберите доступную модель и инструкцию. Явный тест расходует API-лимит. Устройство вызывает `POST /api/device/chat` с `{ "text": "Привет" }`. История диалога не сохраняется; голос здесь не подключён.
6. Если нужен Telegram: создайте собственного бота, начните разговор с ним и определите chat ID по [официальной инструкции](https://core.telegram.org/bots/tutorial). Введите token/chat ID в панели. Нажмите явный тест только когда готовы отправить настоящее сообщение в свой чат. При включении уведомлений новые события могут отправляться в Telegram. Открытие панели ничего не отправляет.

Полный контракт — [docs/API.md](docs/API.md). Помощник может автоматизировать локальные проверки, читая секреты внутри процесса, но не выводя их, заголовки Authorization/Cookie, тела настроек или URL Telegram с токеном. Для автоматических тестов интеграций используйте подменный транспорт, а не чужой чат и реальные API-списания.

## Резервная копия

Остановите запись перед копированием. Ниже базовый локальный вариант; для HTTPS заменяйте каждое `docker compose` на `docker compose -f compose.yaml -f compose.https.yaml`:

```sh
docker compose stop
umask 077
mkdir -p ../kibi-backups
tar -czf "../kibi-backups/kibi-data-$(date +%Y%m%d-%H%M%S).tar.gz" .data
docker compose up -d
```

Архив содержит **секреты**. Храните его вне репозитория, шифруйте для внешнего хранения и ограничивайте доступ. Сохраняйте всю `.data`, включая admin-password, ключ шифрования и состояние; одиночного JSON-файла недостаточно. Запишите также идентификатор коммита, используемые образы, UID/GID и домен без ключей. Caddy-тома содержат приватные ключи сертификатов: резервируйте их отдельно защищённым способом, если нужно сохранить сертификаты, или учитывайте получение новых и лимиты CA.

Для восстановления остановите сервер; оставьте текущую `.data` как отдельную защищённую копию, **не сливайте** две базы. Восстановите архив в новый закрытый каталог, проверьте обычные файлы без ссылок, владельца UID/GID, права каталога `0700` и секретов `0600`. Верните совместимую версию кода и запустите `npm run init` (или контейнерный init) для проверки без перезаписи. Затем запустите сервер и повторите вход, здоровье и проверку сохранённых устройств. Не удаляйте ключ шифрования ради исправления ошибки чтения. Восстановление архива с другого компьютера может требовать согласованной смены владельца; это отдельное разрешённое вами действие администратора.

## Обновление

Сначала сделайте остановленную резервную копию. Проверьте изменения исходников и release notes; сохраните предыдущий полный commit SHA. Получите репозиторий через `git fetch origin`, выберите и проверьте конкретный новый коммит, затем переключитесь на него. Не выполняйте `git reset --hard` поверх своих изменений и не пересоздавайте `.data`.

```sh
npm test
docker compose build
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:4391/api/health
```

Без Node на хосте тесты нужно выполнить в отдельной среде с Node 24; рабочий runtime-образ намеренно не включает тесты. Для HTTPS используйте оба файла и проверяйте публичный HTTPS health. Убедитесь, что вход, устройства и события сохранились. Возврат версии кода делайте с совместимой сохранённой `.data`; при изменении формата хранилища восстановите согласованный снимок. Не используйте `down -v`, `rm -rf .data`, очистку томов или новый ключ как часть обычного обновления.

## Если не запускается

`permission denied`: сравните владельца `.data` с KIBI_UID/KIBI_GID и убедитесь, что это обычный пользователь. `Origin`/CSRF: используйте ровно настроенный URL, войдите заново, не добавляйте wildcard Origin. Ошибка HTTPS: проверьте DNS A/AAAA, доступность 80/443 и конфликт с другим proxy. Ошибка ИИ: проверьте доступ к модели, API-лимит и ключ в панели; не отправляйте ключ в чат. Ошибка Telegram: проверьте token/chat ID и права бота у себя. Не публикуйте полный дамп `.data` или секретные журналы для диагностики.
