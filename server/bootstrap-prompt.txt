Помоги мне развернуть и настроить мой Kibi Server из https://github.com/ezggwp1216-pixel/kibi-studio/tree/codex/kibi-server/server . Это самостоятельная папка server/ в ветке codex/kibi-server общего публичного репозитория; запуск Studio не требуется. Нужна работающая система с веб-панелью, своими устройствами, текстовым ИИ, событиями и, если выберу, Telegram. Работаем только с моим компьютером/сервером; не используй чужую инфраструктуру, персональные проекты Studio или готовые секреты.

В этой версии есть регистрация пользователей по email и паролю и отдельный вход владельца по прежнему паролю администратора. Не смешивай их данные. Сообщи, что почтовая доставка, подтверждение адреса и восстановление пароля пока не подключены. Сохраняй весь каталог данных, включая accounts.json и accounts/ с отдельными ключами. Для локальной Studio прочитай docs/LOCAL_STUDIO.md и docs/SDK.md, предложи копируемый мастер-промпт и привязку устройства по одноразовому коду. Старое приложение требует реализации протокола; сервер не меняет его автоматически. Валидация .kibiplugin не означает установки или исполнения: изолированный исполнитель пока не реализован. Голосовой пилот и его личный аккаунт доступны только владельцу; не передавай их зарегистрированным пользователям.

Сначала прочитай README.md, START_HERE.md, AGENTS.md, docs/API.md и docs/MODULES.md из выбранного репозитория. Проверь ОС, архитектуру, Node, Git, Docker и Compose, доступные порты и существующую установку. Если репозитория ещё нет, клонируй публичный источник в новый каталог командой git clone --branch codex/kibi-server --depth 1 https://github.com/ezggwp1216-pixel/kibi-studio.git, затем работай из kibi-studio/server; сверяй полный commit SHA с GitHub и закрепи выбранный коммит; зафиксируй его в отчёте. Не исполняй случайный скрипт до проверки происхождения. При существующей установке сначала сохрани её данные и исходники, не клонируй поверх.

Спроси только недостающие решения: локально или публично, какой мой домен для HTTPS, какие модули нужны, как должен отвечать текстовый ИИ. Не проси секреты в чате. Обычная установка необходимых официальных компонентов и запуск уже входят в мою задачу: выполняй их без повторного запроса разрешения. Используй официальные инструкции для ОС и учитывай ранее согласованный публичный/локальный режим. Спроси только о новых расходах, удалении/перезаписи данных, действиях с чужими файлами или ещё не согласованных существенных изменениях безопасности, например открытии сервера в Интернет. Не делай root-скрипт установки, curl|sh, автоматическую смену firewall, подключение docker.sock в приложение или включение публичного HTTP вместо HTTPS.

Выбери локальный Node 24+ либо Docker Compose v2. У проекта нет runtime npm-зависимостей. Сначала проверь существующую .data и её владельца: не удаляй и не перезаписывай пароль, ключ шифрования, интеграции или устройства. Не обходи отказ на symlink/hardlink. Выполни init из инструкции; он создаёт admin-password один раз, каталог 0700 и файл 0600 и не выводит пароль. Для Docker используй обычного пользователя (UID не 0), выставь KIBI_UID/KIBI_GID владельца .data; без Node на хосте используй контейнерный init после создания обычного закрытого .data. Не ослабляй права; изменение владельца выполняй только в пределах уже разрешённой установки и после проверки правильного UID/GID. Сервер запускается одним экземпляром на каталог данных.

Пароль панели покажи мне способом просмотра в моём локальном терминале, но сам не вызывай cat ради вывода секрета в чат/журнал инструмента. Не печатай ключи, device tokens, cookies, CSRF, Authorization, содержимое .data и URL Telegram с токеном. Для автоматических проверок читай секрет внутри локального процесса и выводи только результат/код проверки. Я сам введу пароль и ключи через защищённую панель. Не сохраняй секреты в исходники, .env, Dockerfile, промпты или Git.

По умолчанию панель доступна только по http://127.0.0.1:4391 . Для публичного сервера используй compose.yaml + compose.https.yaml и Caddy: мой DNS hostname в KIBI_DOMAIN, точный Origin https://этот-домен, корректные A/AAAA, доступные TCP 80/443. Не переоткрывай существующие порты без согласования. Сертификат должен проверяться без -k. Сохрани несекретные UID/GID/domain для последующих запусков. Контейнер приложения должен работать без root, с read-only корнем, без capabilities и с постоянным каталогом данных.

Запусти тесты и проверь HTTP health, браузерный вход, пустое состояние новой установки, создание отдельного устройства, событие с его Bearer token, подавление повторного eventId, очередь сообщения и ack. Перезапусти сервер и проверь сохранность данных. Удали тестовое устройство и проверь отказ старому токену. Проверь запрет чужого Origin и отсутствие секретов в API. Пиши отчёт только о реально выполненных проверках: локальный запуск не равен проверке моего VPS или платы.

Для текстового ИИ используй существующий модуль OpenAI Responses: я введу собственный API-ключ в панели, выберу доступную модель (исходно gpt-5-mini) и системную инструкцию. Объясни, что запросы могут расходовать мой API-лимит; доступ к моему помощнику разработки/подписке не является настройкой API сервера. Устройство вызывает POST /api/device/chat с {text} и получает {ok:true,text}; это отдельные запросы без истории. Не отправляй реальный платный тест без моего явного согласия; автоматические тесты — через подменный транспорт.

Telegram настраивай только если я выбрал его: собственные bot token/chat ID я ввожу в панели. Настоящую тестовую отправку в мой чат делай только после явного согласия. Объясни, что включённые уведомления будут отправлять новые события. Не отправляй сообщения автоматически при просмотре панели или запуске тестов.

Помоги подключить устройство по docs/API.md с индивидуальным отзываемым токеном и HTTPS. Если я захочу новую функцию, сначала опиши её входы, выходы, настройки и обработку ошибок по docs/MODULES.md, затем измени код с тестами, сохраняя авторизацию/CSRF, шифрование и ограниченные очереди. Произвольные адреса провайдеров, обход проверок TLS и секреты на клиенте недопустимы. Для голоса и аудиопотока прочитай docs/VOICE.md: в комплекте есть выключенный по умолчанию TLS-шлюз с явным выбором Xiaozhi или OpenAI Realtime (gpt-realtime). Для Xiaozhi нужен мой аккаунт xiaozhi.me: выбери один проект/устройство, получи код в панели, помоги мне привязать отдельного программного клиента и выбери модель/язык в официальной консоли. Фабричные ключи и обход аттестации не используй; MQTT-only конфигурация пока не поддерживается. Официальное облако Xiaozhi в бесплатном Open Source режиме разрешает только учебное использование и запрещает коммерческие/production-сценарии: для личного теста покажи владельцу соглашение и дождись его принятия; для сервиса пользователям выбери другой лицензированный вариант. Не подключай GitHub без отдельного разрешения: в консоли он может требоваться для Qwen, тогда как без проверки доступна Xiaozhi Lite. Не обещай бессрочный бесплатный доступ или конкретную модель до проверки. Не включай OpenAI автоматически при сбое Xiaozhi; можно зафиксировать KIBI_VOICE_PROVIDER=xiaozhi в настройке запуска. Настрой выбранный режим безопасно и проверь отдельно; готовность шлюза не означает работоспособность физической Киби. Расписания, физическое подключение платы и сборку прошивки не называй проверенными до их фактической проверки. Для редактора/сборки используй отдельный Kibi Studio, если я это попрошу.
