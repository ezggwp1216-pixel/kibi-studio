# Публичные модули для Киби Studio

Этот каталог добавляет подключение аккаунта Киби и работу с публичными ресурсами в **уже установленную публичную Studio 0.3**. Он не содержит весь редактор, компилятор, SDK и установочный архив Studio. Для новой установки сначала нужен полный публичный комплект Studio; один этот каталог его не заменяет.

Код модулей самостоятельный: Node 24, стандартные библиотеки, без установки npm-зависимостей. Здесь нет пользовательских проектов, настроек установленной Studio, паролей, токенов или готовых персонализированных прошивок.

## Обновление установленной публичной Studio 0.3

Обновлятор знает точные контрольные суммы публичной исходной версии KibiVirtual-dev и соответствующей версии после подключения модулей. Сходного номера версии недостаточно: другая ветка, изменённый файл программы или неизвестный прежний модуль остановят обновление до записи. Закрытые и персональные сборки не являются поддерживаемой исходной версией этого обновлятора.

1. Остановите локальную Studio. Используйте Node 24 или новее.
2. Откройте каталог этого публичного репозитория и сначала запустите проверку:

   ```sh
   node studio/upgrade.mjs --root "/абсолютный/путь/к/Studio"
   ```

   По умолчанию это только проверка: выводится список создаваемых и изменяемых файлов, ничего не записывается. Сеть, скачивание ресурсов и запуск кода Studio при проверке не используются.

3. Проверьте выбранный каталог и примените готовое обновление:

   ```sh
   node studio/upgrade.mjs --root "/абсолютный/путь/к/Studio" --apply
   ```

4. Запустите Studio обычным способом и откройте её локальную страницу. В заголовке появится кнопка «Аккаунт». Если обновление уже полностью установлено, повторный запуск вернёт `already-current` без новых записей и резервных копий.

Если обновление изменило набор инструментов ИИ, следующее сообщение создаст новый внутренний диалог с актуальными инструментами. История в окне Studio, исходники, настройки и сборки сохраняются. Модель получает текущий контекст проекта и может перечитать его исходники; старая внутренняя история ChatGPT автоматически не переносится. При последующих сообщениях и перезапусках тот же набор инструментов продолжает уже созданный диалог.

Обновлятор сначала проверяет все известные файлы и готовые преобразования. Затем сохраняет прежние **файлы программы** в отдельный каталог `.kibi-studio-upgrade-*` внутри выбранной Studio: каталоги имеют права `0700`, файлы — `0600`. Каталог и его путь возвращаются в отчёте. Это резервная копия программы, а не проектов или настроек.

Программа обновления обращается только к явному списку файлов `src/`, `web/`, неизменяемому `native/support.mjs` и четырём публичным инструкциям. Она не обходит каталог Studio и не читает `projects/`, `.studio/`, настройки, ключи или данные входа. При ошибке записи уже заменённые программные файлы восстанавливаются; новые файлы удаляются. Если восстановление невозможно из-за состояния диска или чужих изменений, отчёт содержит `upgrade_rollback_failed`, путь к резервной копии и список невосстановленных файлов. Такое состояние требует восстановления программы перед её запуском.

Выпуск `studio-platform-2026-11-10-user-diagnostics` добавляет чтение безопасной диагностики своей Киби в окне аккаунта и инструмент `kibi_device_diagnostics` для ИИ. Сервер должен поддерживать новый маршрут диагностики; чтение не запускает разговор. Уже установленный предыдущий публичный комплект обновляется только при точном совпадении хешей его шести изменённых модулей и инструкций. Неизвестные локальные правки не перезаписываются. Данные аккаунта и проектов сохраняются.

## Что устанавливается

| Файл | Назначение |
| --- | --- |
| `studio-platform.mjs` | Подключение публичных инструментов к серверу Studio, контексту проекта и существующей защите локальных запросов. |
| `studio-account.mjs` | Привязка аккаунта, закрытое локальное хранение отдельного StudioToken, ограниченные запросы устройств и голоса. |
| `public-resources.mjs` | Поиск и чтение публичных HTTPS-источников, чтение разрешённых SDK-заголовков, проверяемый импорт изображений. |
| `managed-assets.mjs` | Установка проверенных ресурсов через хранилище проекта с проверкой актуального проекта и защитой от перезаписи. |
| `leroyd-c309-recipe.json` | Проверяемое описание извлечения публичного ресурса с закреплённой контрольной суммой источника. |
| `studio-account.js`, `studio-account.css` | Локальная форма аккаунта, список собственных устройств, ввод кода Киби и доступная аккаунту кнопка голоса. |
| `src/platform-guides/` | Публичные инструкции API, голоса, аппаратуры и сервисов из этого репозитория. |

Обновлятор добавляет небольшие привязки в известные публичные `server.mjs`, `project-store.mjs`, `codex-bridge.mjs`, `web/app.js` и `web/index.html`. Существующие проверки локального Host, Origin, CSRF, проекта и очереди изменений остаются точкой допуска. Нативные драйверы и лимит **63 исходных файла** не изменяются.

Проверенные ресурсы дописываются к существующему публичному `embedded_assets.h`: штатная часть сохраняет закреплённые исходные байты, новые блоки проходят проверку, а хранилище обновляет защищённую контрольную сумму. Это не замена драйверов и не расширение файлового лимита. Публичные модули не распространяют чужие изображения или неустановленные лицензии: описание рецепта и ссылка на источник не дают прав на использование самого ресурса. Для импортируемого ресурса с неизвестной лицензией статус остаётся `unknown`.

## Подключение аккаунта

Пользователь создаёт одноразовый ключ в личном кабинете Киби Server и вставляет его в поле **«Ключ подключения Studio»** в локальном диалоге. Ключ действует 10 минут и используется один раз. Ключи, пароли, Wi-Fi и API-ключи не вводятся в чат с ИИ.

Сервер выдаёт отдельный StudioToken с абсолютным сроком 90 дней. Клиент сохраняет его только в `.studio/private/account-connection.json` с правами `0600`; закрытые родительские каталоги имеют права `0700`. Токен не возвращается инструментам ИИ, браузеру или журналу. В интерфейсе доступны безопасные сведения об аккаунте и подключении. Подключение можно отозвать в кабинете либо явно отключить из Studio.

Разрешения StudioToken ограничены `pairing.claim`, `devices.list`, `voice.status`, `voice.activate`, `catalog.read`. Он не является паролем сайта, ключом провайдера или токеном устройства и не даёт административных настроек. Адрес сервера задаёт доверенная конфигурация локального приложения; ответ сервера или запрос ИИ его не меняет.

Адрес электронной почты сейчас служит идентификатором входа: доставка писем, подтверждение адреса и восстановление пароля не настроены. Регистрация аккаунта сама по себе не включает голос.

## Свой Киби и текущий голосовой пилот

Устройство начинает обычную процедуру привязки, показывает короткий код и само опрашивает результат с отдельным секретом. Пользователь вводит **«Код с экрана Киби»** в Studio. Studio подтверждает привязку, а индивидуальный deviceToken получает только устройство. StudioToken не помещается в прошивку.

Кнопка «Подключить голос» доступна только при фактическом разрешении сервера и выборе собственного устройства. Текущий общий Xiaozhi-пилот требует отдельного одобрения владельцем сервера одного аккаунта; сервер дополнительно проверяет принадлежность устройства и состояние настройки Xiaozhi. Studio не может сама выдать это разрешение, сменить провайдера или включить платный запасной сервис.

Статусы берутся из API. Слушающий шлюз, успешно собранный код или картинка предпросмотра не доказывают доступ к провайдеру и физический звук. Обновление программы Studio также не изменяет автоматически уже установленную прошивку Киби: привязка, проверка TLS и безопасное хранение deviceToken должны быть реализованы в самой прошивке. Расписания остаются запланированной возможностью.

## Для интеграции модулей

`createStudioPlatform()` принимает доверенные `root`, `getStore`, `getEpoch`, `announce`, `mutate`; локальные маршруты подключаются после существующих проверок запроса. `platformTools` и `platformInstructions` добавляются в набор инструментов и инструкции агента. `platform.context()` дополняет контекст проекта, `platform.close()` завершает принадлежащие модулю операции. Обновлятор делает эти привязки только в известных публичных точках.

В браузере `initStudioAccountUI({api,mount})` вызывается после создания `window.studio`; локальный `api(path,{method,body})` передаёт `body` как объект и сам добавляет CSRF. Интерфейс не выдаёт ключи и не запускает привязку, активацию голоса или проверки провайдера при загрузке страницы.

Инструменты чтения публичных ресурсов принимают внешние документы как недоверенные данные, не исполняют скачанный код и не устанавливают зависимости. Импорт проходит через доверенное хранилище текущего проекта. Изменение проекта во время операции отменяет её; неизменяемые блоки ресурсов отделены от редактируемого кода приложения. Компиляция и проверка платы остаются задачами полного установленного комплекта Studio.
