# Публичные модули для Киби Studio

Этот каталог добавляет подключение аккаунта Киби, профиль помощника, готовый голосовой модуль и работу с публичными ресурсами в **уже установленную совместимую Studio 0.3**. Он не содержит весь редактор, компилятор, полный SDK и установочный архив Studio. Для новой установки сначала нужен полный публичный комплект Studio; один этот каталог его не заменяет.

Код модулей самостоятельный: Node 24, стандартные библиотеки, без установки npm-зависимостей. Здесь нет пользовательских проектов, настроек установленной Studio, паролей, токенов или готовых персонализированных прошивок.

## Обновление установленной публичной Studio 0.3

Обновлятор знает точные контрольные суммы публичной исходной версии KibiVirtual-dev и отдельно проверенного программного варианта установленной Studio. Сходного номера версии недостаточно: другая ветка, изменённый файл программы или неизвестный прежний модуль остановят обновление до записи. Наличие своей Studio не разрешает автоматически добавлять её hash в список: новый программный вариант требует проверки. Пользовательские проекты в этот список не входят.

1. Остановите локальную Studio. Используйте Node 24 или новее.
2. Откройте каталог этого публичного репозитория и сначала запустите проверку:

   ```sh
   node studio/upgrade.mjs --root "/абсолютный/путь/к/Studio"
   ```

   По умолчанию это только проверка: выводится список создаваемых и изменяемых файлов, ничего не записывается. Сеть, скачивание ресурсов и запуск кода Studio при проверке не используются.

3. Проверьте выбранный каталог и примените готовое обновление:

   ```sh
   node studio/upgrade.mjs --root "/абсолютный/путь/к/Studio" --apply
   ```

4. Запустите Studio обычным способом и откройте её локальную страницу. В заголовке появится кнопка «Аккаунт». Если обновление уже полностью установлено, повторный запуск вернёт `already-current` без новых записей и резервных копий.

Если обновление изменило инструменты или инструкции ИИ, следующее сообщение создаст новый внутренний диалог с актуальными правилами. История в окне Studio, исходники, настройки и сборки сохраняются. Модель получает текущий контекст проекта и может перечитать его исходники; старая внутренняя история ChatGPT автоматически не переносится. При последующих сообщениях и перезапусках та же версия правил продолжает уже созданный диалог.

Обновлятор сначала проверяет все известные файлы и готовые преобразования. Затем сохраняет прежние **файлы программы** в отдельный каталог `.kibi-studio-upgrade-*` внутри выбранной Studio: каталоги имеют права `0700`, файлы — `0600`. Каталог и его путь возвращаются в отчёте. Это резервная копия программы, а не проектов или настроек.

Программа обновления обращается только к явному списку программных файлов `src/`, `web/`, `native/support.mjs` и публичным инструкциям. Она не обходит каталог Studio и не читает `projects/`, `.studio/`, настройки, ключи или данные входа. При ошибке записи уже заменённые программные файлы восстанавливаются; новые файлы удаляются. Если восстановление невозможно из-за состояния диска или чужих изменений, отчёт содержит `upgrade_rollback_failed`, путь к резервной копии и список невосстановленных файлов. Такое состояние требует восстановления программы перед её запуском.

Текущий публичный оверлей включает безопасную диагностику своей Киби, профиль помощника и инструменты `kibi_device_diagnostics`, `kibi_get_assistant`, `kibi_set_assistant`. Сервер должен поддерживать соответствующие маршруты. Чтение диагностики или профиля не запускает разговор; сохранение профиля не применяет роль в облаке автоматически. Уже установленный комплект обновляется только при точном совпадении известных хешей программы, модулей и инструкций. Неизвестные локальные правки не перезаписываются. Данные аккаунта и проектов сохраняются. Наличие исходников оверлея здесь не доказывает, что он уже установлен в конкретной Studio или развёрнут на сервере.

## Что устанавливается

| Файл | Назначение |
| --- | --- |
| `studio-platform.mjs` | Подключение публичных инструментов к серверу Studio, контексту проекта и существующей защите локальных запросов. |
| `studio-account.mjs` | Привязка аккаунта, закрытое хранение StudioToken, ограниченные запросы устройств, личного голоса и профиля помощника. |
| `public-resources.mjs` | Поиск и чтение публичных HTTPS-источников, чтение разрешённых SDK-заголовков, проверяемый импорт изображений. |
| `managed-assets.mjs` | Установка проверенных ресурсов через хранилище проекта с проверкой актуального проекта и защитой от перезаписи. |
| `png-raster.mjs` | Подготовка PNG в переносимый RGB565/alpha ресурс на компьютере; один helper для предпросмотра и платы. |
| `device-modules.mjs`, `device-modules.json`, `device-module-install.mjs` | Каталог, точные хеши двух заголовков Xiaozhi и зависимостей SDK, установка с проверкой проекта и отказом неизвестным изменениям. |
| `src/device-sdk/kibi_xiaozhi_*.h` | Обезличенный голосовой механизм, явно подключаемый в проект через `kibi_enable_module`. |
| `project-readiness.mjs` | Разделение нативных проверок, настроек и target-сборки; конкретные причины остановки. |
| `leroyd-c309-recipe.json` | Проверяемое описание извлечения публичного ресурса с закреплённой контрольной суммой источника. |
| `studio-account.js`, `studio-account.css` | Форма аккаунта, собственные устройства, код Киби, голос и редактор характера/контекста/разрешённых действий с копированием роли. |
| `src/platform-guides/` | Публичные инструкции API, голоса, аппаратуры и сервисов из этого репозитория. |

Обновлятор добавляет небольшие привязки в известные программные файлы. Существующие проверки локального Host, Origin, CSRF, проекта и очереди изменений остаются точкой допуска. `app_core.h` и `app_view.h` доступны для переносимого макета; `app_feature.h` — после явного «Проект готов», с сохранением этого разрешения на итерации. Проверки и бинарники всё равно аннулируются при изменении исходников. Драйверы остаются защищены. Локальный предел увеличен до **96 исходных файлов**, чтобы два заголовка модуля помещались рядом со штатной базой; ограничения 4 MiB суммарных исходников и 2 MiB банка изображений сохранены. Удалённый компилятор должен поддерживать такой же предел.

Проверенные ресурсы дописываются к существующему публичному `embedded_assets.h`: штатная часть сохраняет закреплённые исходные байты, новые блоки проходят проверку, а хранилище обновляет защищённую контрольную сумму. PNG получает готовые `ReadPixel`/`DecodeRow`; он не требует декодера в коде приложения. Публичные модули не распространяют чужие изображения или неустановленные лицензии: описание рецепта и ссылка на источник не дают прав на использование самого ресурса. Для импортируемого ресурса с неизвестной лицензией статус остаётся `unknown`.

## Подключение аккаунта

Пользователь создаёт одноразовый ключ в личном кабинете Киби Server и вставляет его в поле **«Ключ подключения Studio»** в локальном диалоге. Ключ действует 10 минут и используется один раз. Ключи, пароли, Wi-Fi и API-ключи не вводятся в чат с ИИ.

Сервер выдаёт отдельный StudioToken с абсолютным сроком 90 дней. Клиент сохраняет его только в `.studio/private/account-connection.json` с правами `0600`; закрытые родительские каталоги имеют права `0700`. Токен не возвращается инструментам ИИ, браузеру или журналу. В интерфейсе доступны безопасные сведения об аккаунте и подключении. Подключение можно отозвать в кабинете либо явно отключить из Studio.

Новые подключения StudioToken ограничены семью правами: `pairing.claim`, `devices.list`, `voice.status`, `voice.activate`, `catalog.read`, `assistant.read`, `assistant.write`. Уже выданный токен с пятью правами сохраняет только эти пять; для редактора помощника нужен свежий одноразовый код и переподключение Studio. Автоматического расширения прав нет. Токен не является паролем сайта, ключом провайдера или токеном устройства и не даёт административных настроек. Адрес сервера задаёт доверенная конфигурация локального приложения; ответ сервера или запрос ИИ его не меняет.

Адрес электронной почты сейчас служит идентификатором входа: доставка писем, подтверждение адреса и восстановление пароля не настроены. Регистрация аккаунта сама по себе не включает голос.

## Своя Киби, личный Xiaozhi и отдельный пилот

Устройство начинает обычную процедуру привязки, показывает короткий код и само опрашивает результат с отдельным секретом. Пользователь вводит **«Код с экрана Киби»** в Studio. Studio подтверждает привязку, а индивидуальный deviceToken получает только устройство. StudioToken не помещается в прошивку.

Для личного Xiaozhi пользователь получает код в своём кабинете Kibi Server, добавляет устройство в собственного агента на официальном сайте, проверяет привязку и выбирает свою Киби. Пароль Xiaozhi не собирается; регистрация зашифрована собственным ключом кабинета. «Подключить голос» и `kibi_activate_voice({deviceId})` выбирают устройство для этого личного подключения при фактической готовности сервера. Ошибки и отключение личной регистрации не возвращают общий агент владельца или платный OpenAI: личный режим сохраняется до новой привязки.

Общий Xiaozhi-пилот остаётся отдельным путём с одобрением владельцем одного кабинета; Studio не может выдать себе этот допуск или менять ключи провайдера. Сохранённые данные и выбранное устройство владельца не заменяются личными регистрациями. Один TLS listener обслуживает до четырёх разговоров: по одному на личный кабинет и одно место для владельца/общего пилота. Чужие разговоры и регистрационные коды не показываются.

Статусы берутся из API. Слушающий шлюз, успешно собранный код или картинка предпросмотра не доказывают доступ к провайдеру и физический звук. Обновление программы Studio также не изменяет автоматически уже установленную прошивку Киби: привязка, проверка TLS и безопасное хранение deviceToken должны быть реализованы в самой прошивке. Расписания остаются запланированной возможностью.

## Помощник Киби

В окне «Аккаунт» выберите свою Киби в разделе «Помощник Киби» и загрузите профиль.
Редактор содержит характер (до 4000 символов), контекст (до 6000) и два разрешаемых
действия: `kibi.get_device_status` и `kibi.notify`. Данные хранятся зашифрованно
на сервере по устройству, а ответ содержит текущую `revision`. Не сохраняйте
секреты в этих полях: по разрешённому запросу их читает модель.

Модель использует `kibi_get_assistant({deviceId})` и
`kibi_set_assistant({deviceId,character,context,actions})` после согласования с
пользователем. Клиент обращается к `GET/POST api/studio/devices/:id/assistant`
только с нужным правом и проверяет принадлежность/идентичность ответа. Локальный
маршрут оверлея — `/api/account/devices/:id/assistant`; обычная защита Host,
Origin и CSRF остаётся у Studio. Изменённая форма сохраняется при ошибке;
чужие/запоздалые ответы не должны заменять выбранный профиль.

После сохранения доступна кнопка «Скопировать роль». Пользователь вручную
вставляет `rolePrompt` в своего агента Xiaozhi один раз и после изменения
характера. `application:{mode:"manual_xiaozhi",status:"manual_step_required"}`
означает именно этот ручной шаг: сохранение на сервере не меняет системную
инструкцию облака. Недокументированный API консоли не используется.

При личном соединении серверный MCP всегда предлагает `kibi.get_context` с
текущим профилем как данными инструмента. Это не system prompt и не доказательство,
что облачная модель запросила или использовала данные. Два дополнительных
действия выполняются только с текущим разрешением профиля и для этой Киби:
`kibi.get_device_status` читает сохранённые имя/связь/время последнего запроса,
`kibi.notify` ставит сообщение в существующую очередь. Очередь не подтверждает
доставку или показ. Заряд, громкость, яркость, лица и таймер не являются готовыми
серверными инструментами. Автоматической памяти бесед и выполнения произвольного
пользовательского кода нет; `.kibiplugin` по-прежнему только валидируется.

## Для интеграции модулей

`createStudioPlatform()` принимает доверенные `root`, `getStore`, `getEpoch`, `announce`, `mutate`; локальные маршруты подключаются после существующих проверок запроса. `platformTools` и `platformInstructions` добавляются в набор инструментов и инструкции агента. `platform.context()` дополняет контекст проекта, `platform.close()` завершает принадлежащие модулю операции. Обновлятор делает эти привязки только в известных публичных точках.

В браузере `initStudioAccountUI({api,mount})` вызывается после создания `window.studio`; локальный `api(path,{method,body})` передаёт `body` как объект и сам добавляет CSRF. Интерфейс не выдаёт ключи и не запускает привязку, активацию голоса или проверки провайдера при загрузке страницы.

Инструменты чтения публичных ресурсов принимают внешние документы как недоверенные данные, не исполняют скачанный код и не устанавливают зависимости. Импорт проходит через доверенное хранилище текущего проекта. Изменение проекта во время операции отменяет её; неизменяемые блоки ресурсов отделены от редактируемого кода приложения. Компиляция и проверка платы остаются задачами полного установленного комплекта Studio.
