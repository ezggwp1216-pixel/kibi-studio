# Модули и устройство

Kibi Server — изменяемый исходный код с общим хранилищем и HTTP API. Здесь нет загрузки сторонних плагинов, автоматического обнаружения модулей или исполнения кода, присланного устройством. Новую функцию добавляют изменением исходников, тестами и обновлением своего экземпляра.

## Что уже подключено

| Модуль | Поведение |
| --- | --- |
| `notifications` | Устройства с индивидуальными токенами, локальные события, сообщения на устройство с ack |
| `ai` | Отдельные текстовые запросы к OpenAI Responses, своя модель и инструкция; включается после настройки собственного ключа |
| `telegram` | Зашифрованные token/chat ID, включение отправки новых событий, отдельный явный тест |
| `voice` | Реализован TLS WebSocket-шлюз OpenAI Realtime с Opus; по умолчанию выключен, требует TLS, серверный ключ и совместимое устройство. [Настройка и состояния](VOICE.md) |
| `schedules` | Запланирован; фонового планировщика пока нет |

Статус `configured` сообщает о сохранённых настройках, а не о проверенной доступности провайдера. Для фактической проверки нужен явный тест. Текстовый ИИ не сохраняет историю между запросами и не выполняет команды на устройстве. Ввод устройства и инструкция отправляются провайдеру; заранее оцените, какие данные допустимо передавать. API-ключ сервера и доступ к ИИ для разработки проекта настраиваются отдельно.

## Контракт расширения

Перед реализацией опишите имя и стабильный ID модуля, назначение, вход/выход, настройки, ограничения, ошибки и проверку. Реестр статусов в `/api/overview` должен показывать только действительную реализацию. Общая основа:

1. Административные изменения проходят существующую проверку сессии, точного Origin и CSRF. Не добавляйте публичный обход авторизации ради тестовой кнопки. Device route проверяет индивидуальный Bearer-токен; устройство может работать только со своими данными.
2. Данные валидируются до изменения состояния. Не повышайте общий лимит JSON 16 КиБ без отдельного решения. Возвращайте фиксированные коды ошибок `{ok:false,code}`; исключения, URL с токеном и ответы провайдера не возвращайте клиенту и не печатайте.
3. Ключи сохраняются через существующее зашифрованное хранилище в `.data/state.json` с `.data/encryption.key` (32 байта). API настроек возвращает безопасные флаги вместо ключей. Не кладите секреты в `web/`, `.env`, код и историю Git.
4. Внешний транспорт получает внедряемый `fetchImpl`, имеет таймаут, предел ответа и фиксированный HTTPS host. Запрещены произвольные URL из запроса, перенаправления на другой адрес и отключение TLS. Telegram допускает только `api.telegram.org`, текстовый ИИ — только официальный OpenAI API. Произвольный адрес создаёт риск доступа к внутренним сервисам хоста.
5. Сначала сохраните локальное событие, затем выполните разрешённую внешнюю отправку и зафиксируйте её результат. Ошибка доставки не должна уничтожать событие. Дедупликация по `eventId` действует отдельно для каждого устройства, пока соответствующее событие сохраняется среди последних 200. Это не гарантия однократной доставки при любых сбоях.
6. Тесты проверяют реальный маршрут/состояние и подменяют только внешний транспорт. Без настоящих ключей, платных запросов и сообщений в реальные чаты. Новая внешняя операция требует явного действия пользователя; не запускайте её при чтении страницы или healthcheck.

Лимиты текущей основы на кабинет: 50 устройств, 50 ожидающих сообщений на устройство, 200 недавних событий; сессия 12 часов, максимум 8 сессий на кабинет и 1024 суммарно. Всего до 128 зарегистрированных пользователей. Частота ограничена: 10 попыток входа/регистрации в минуту по адресу соединения, 240 запросов панели в минуту на сессию, 120 запросов устройства в минуту на токен. Заголовки прокси не считаются достоверным адресом клиента: при общем reverse proxy лимит входа может быть общим для его пользователей. Для публичной расширенной эксплуатации отдельно проектируйте квоты и аудит; не обещайте их наличие в этой основе.

## Безопасный пример функции

В [src/module-example.mjs](../src/module-example.mjs) экспортируется чистая функция `summarizeEvent(event)`. Она принимает объект события и возвращает `{title,message,deviceId}`. Её можно использовать для подготовки локального отображения/уведомления. Пример вызова:

```js
import { summarizeEvent } from './src/module-example.mjs';

const summary = summarizeEvent({
  id: 'example-event',
  title: 'Кнопка нажата',
  message: 'Локальное действие пользователя',
  deviceId: 'example-device',
  createdAt: new Date().toISOString(),
  delivery: 'local',
});
// summary: {title: 'Кнопка нажата',
//           message: 'Локальное действие пользователя', deviceId: 'example-device'}
```

Это пример преобразования данных, а не готовая регистрация плагина и не отправка в сеть. Чтобы добавить действие, найдите обработчик нужного маршрута в [src/server.mjs](../src/server.mjs), сохраните его проверки доступа и используйте проверенные входные данные. Вынесите преобразование/доставку в отдельную функцию, добавьте тесты успеха, отказа в доступе, неправильного входа и отказа внешнего сервиса. Если нужен новый маршрут/настройка, сначала обновите [API.md](API.md), затем сервер и панель; сам импорт функции не создаёт маршрут. Строки события показывайте как текст, не вставляйте их через `innerHTML`.

## Подключение устройства

Основной путь: совместимое приложение Киби получает одноразовый код, пользователь подтверждает его в своём кабинете, устройство забирает индивидуальный токен своим секретом опроса. См. [SDK](SDK.md) и [инструкцию локальной Studio](LOCAL_STUDIO.md). Старым приложениям нужно добавить протокол через Studio; кнопка в панели сама не меняет прошивку. Ручной путь: создайте устройство в панели и сохраните показанный один раз токен на устройстве через защищённый способ настройки. Администраторский пароль и ключ OpenAI/Telegram на устройство не передаются. Комплект не собирает и не прошивает код автоматически.

## SDK и пользовательские пакеты

Структура `.kibiplugin` и валидатор доступны в [SDK.md](SDK.md). Проверка JSON не устанавливает и не запускает код. Выполнение произвольного кода требует отдельного изолированного исполнителя с квотами; загрузчик и такой исполнитель пока не реализованы. Не добавляйте `eval`, динамический импорт загруженного файла или `node:vm` в HTTP-процесс. Данные кабинетов изолированы приложением; это не изоляция выполнения недоверенного кода.

Каждый запрос устройства использует `Authorization: Bearer <его токен>` и HTTPS для удалённого подключения. Браузерные cookie/CSRF ему не нужны. Маршруты и полные поля описаны в [API.md](API.md):

- `POST /api/device/events` — `{title,message,eventId?}`. Для повторной попытки используйте тот же `eventId`. Проверяйте `{ok:true,eventId,duplicate}`; не генерируйте новый ID при каждом сетевом повторе.
- `GET /api/device/messages` — список сообщений `{id,title,message,createdAt}`. После обработки каждого сообщения отправьте `POST /api/device/ack` с `{messageId}`. Сохраняйте факт обработки, если повторное выполнение опасно: потерянный ack может привести к повторному получению.
- `POST /api/device/chat` — `{text}`; ответ `{ok:true,text}`. Провайдер, модель и инструкция задаются в панели. Локальная история разговора не передаётся автоматически. Не повторяйте платный запрос бесконечно при сбое; используйте ограниченные попытки и паузы.

Обрабатывайте недоступную сеть и фиксированные ошибки, ограничивайте частоту запросов и не отключайте проверку сертификатов ради подключения. `not_seen` означает отсутствие запросов, `online` — запрос не старше 90 секунд, `offline` — более старую связь; это не доказательство фактического состояния питания платы. Удаление устройства отзывает токен. При утере токена создайте новое устройство; восстановить исходный токен из хеша нельзя.

Для подготовки приложения/прошивки отдельно используйте [Kibi Studio](https://github.com/ezggwp1216-pixel/kibi-studio). Уточните поддержку HTTPS и формат запросов вашей прошивки, добавьте интеграцию по контракту и проверьте на реальной плате. Существование HTTP endpoint само по себе не означает, что конкретная прошивка уже умеет им пользоваться.
