# Надёжная разработка приложений Киби: аудит и исправления

## Запрос
Проверить и обновить инструкции, код и пакеты, чтобы ИИ собирал воспроизводимые
приложения под реальную Киби: микрофон, динамик, дисплей/тач, кнопки, Wi-Fi,
аккумулятор и необязательный Kibi Server. Проверка платы разрешена с обязательным
возвратом последней рабочей разговорной прошивки.

## Решение
Сохраняем действующую платформу и исправляем подтверждённые дефекты. Новая
аппаратная реализация с нуля не требуется: её контракт извлекается из публичного
SDK, сверяется со сборкой и физическим тестом. Рабочий touch и power сохраняются.
Единый версионированный контракт и проверяемый пакет инструкций должны исключить
смешивание старых/новых символов API и голосовых протоколов.

## Подтверждённые разрывы
- SDK источника не содержит уже установленный preparePlayback; установленная и
  исходная connectivity относятся к разным поколениям.
- README нейтральной базы содержит BTC-инструкции и устаревшие результаты тестов.
- Legacy realtime/job PCM helpers не являются новым Opus WebSocket протоколом.
- Новому Wi-Fi controller недоступно восстановление после Stopped/start-failure.
- Сервер меняет живое состояние до сохранения без отката при ошибке диска.
- Сервер/SDK расходятся в допустимом тексте; Telegram и некоторые отказы SDK не
  закрывают/ограничивают входящий ответ; master prompt ошибается в дедупликации.

## Границы
Только публичные SDK/шаблоны/инструкции. Закрытый runtime server Studio, приватные
проекты, настройки, персональные бинарники и журналы не читаются/не копируются.
Генерируемое приложение изменяет модель в локальном окне через kibi-инструменты;
рабочий голосовой проект не переписывается аудиторами. Секреты не входят в SDK,
пакеты, отчёты и контекст ИИ. Сервисы тестируются через внедрённый транспорт;
настоящий внешний запрос требует отдельного явного запуска. Node24 без npm deps.
Новый исполнитель произвольных плагинов, коммерческий Xiaozhi и многопользовательский
голос не объявляются готовыми. Нельзя гарантировать произвольный будущий код;
проверки должны отличать поддерживаемое от заблокированного и непроверенного.

## Приёмка
Регрессии подтверждённых ошибок, 218+ серверных тестов, проверка пакета/его
контракта, отдельная target-сборка публичного теста, проверка UI инструкций.
На плате: микрофон/динамик/две кнопки/тач/дисплей/Wi-Fi/батарея/сон, затем возврат
рабочей разговорной версии. Результаты host/target/server/device/provider
фиксируются раздельно; программный тест не подменяет физическое подтверждение.
