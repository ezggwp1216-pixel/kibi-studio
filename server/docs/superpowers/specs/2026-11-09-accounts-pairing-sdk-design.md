# Личные кабинеты, привязка Киби и SDK

## Цель
Пользователь регистрируется по почте и паролю, получает пустой личный кабинет,
привязывает совместимое приложение Киби по одноразовому коду и использует
опубликованный SDK в локальной Studio. Существующий администратор и его данные
продолжают работать.

## Решения первой версии
- Один HTTP-сервис; отдельное хранилище и ключ шифрования на каждого пользователя.
  Это изоляция данных приложением, а не контейнер для исполнения чужого кода.
- Старый вход только по паролю сохраняет владельца существующего хранилища.
  Регистрация создаёт обычного пользователя без доступа к данным владельца.
- Почта — логин; доставки писем, подтверждения адреса и восстановления пароля пока
  нет. Интерфейс сообщает это до регистрации. Не добавляем фиктивную верификацию.
- Сессии HttpOnly/SameSite/CSRF/Origin, асинхронный scrypt, ограниченные очереди и
  попытки входа. Все идентификаторы владельца определяются сервером.
- Привязка: устройство получает код и отдельный секрет опроса; пользователь
  подтверждает код в кабинете; устройство забирает индивидуальный токен. Код
  действует 5 минут, завершение одноразовое, отмена/перезапуск обнуляют ожидание.
  Токен не возвращается в кабинет и не попадает в URL, журналы или инструкции ИИ.
- Собственный HTTP API устройства доступен каждому кабинету. Существующий
  голосовой пилот и аккаунт Xiaozhi остаются только у владельца. Многопользовательский
  голос пока недоступен и не изображается готовым.
- SDK: версионированный контракт пакета, валидатор, транспорт привязки/сообщений,
  пример модуля, локальные тесты и мастер-промпт. Валидация не исполняет код.
  Безопасный исполнитель пользовательских плагинов — отдельный следующий этап.
- Локальные инструкции публикуются как самостоятельные общедоступные файлы и
  показываются в панели; закрытые проекты/настройки Studio не читаем и не меняем.

## Приёмка
Два аккаунта не видят устройства, сообщения, события, интеграции и голосовые
состояния друг друга/владельца. Имена устройств не дают права доступа. Привязка
устойчива к неверному секрету, повторному получению и конкурирующему подтверждению.
Данные и токены переживают перезапуск. Старые тесты и голосовые контракты проходят.
Локальный браузер подтверждает регистрацию, вход, привязку и копирование инструкции.
Внешние API и физическая Киби не считаются проверенными этими тестами.
