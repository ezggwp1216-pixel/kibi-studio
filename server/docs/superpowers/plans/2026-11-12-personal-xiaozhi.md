# Personal Xiaozhi Implementation Plan

**Goal:** личная регистрация Xiaozhi, изолированный профиль помощника и проверяемые
серверные действия из Studio.

**Architecture:** независимые контроллеры кабинетов без listener; общий ограниченный
TLS gateway; профиль и встроенный MCP замкнуты на доверенную идентичность кабинета.

**Spec:** ../specs/2026-11-12-personal-xiaozhi-design.md

## Ограничения

Node 24, без новых npm зависимостей; не читать личные проекты/секреты Studio;
сохранить владельца и пилот; не выполнять пользовательский код; внешние тесты
инъецированы. Нет скрытого API роли и обещания автоматического применения роли.

## Задачи

- [x] Контроллер src/account-xiaozhi.mjs и тесты: шифрованная регистрация, выбранная
  собственная Киби, авторизация, отмена, защита от запоздалых записей после отключения.
- [x] Общий gateway: ограниченные независимые соединения, занятость одного кабинета,
  прежний режим maxSessions=1 совместим; тесты TLS с инъецированным адаптером.
- [x] Профили src/assistant.mjs, серверный MCP и точное объявление возможности;
  тесты схем, разрешений, отказов, отсутствие пересечения кабинетов и регрессии аудио.
- [x] Маршруты identity/server, совместимые права Studio; HTTP проверки двух кабинетов.
- [x] Личный кабинет и оверлей Studio: привязка/отключение, выбор Киби, профиль,
  копирование роли, честные статусы и разрешения действий. Проверка широкого/узкого UI.
- [x] Обновить API/VOICE/LOCAL_STUDIO/SDK и пакет оверлея, полный node --test,
  независимый обзор. Публикацию и физический звук подтверждать отдельно.

## Результат

Выпуск установлен на sldvkibi.ru/server/ и в локальную Studio на 4390.
Полный набор: 513 проверок, 504 успешны, 0 ошибок, 9 условных пропусков.
После правки текста интерфейса дополнительно пройдены 25 проверок веб-форм.
Публичный комплект Studio скачан по HTTPS и сверен по SHA-256.
В браузере проверены сохранение/загрузка профиля и узкий экран; пример использовал
синтетический локальный кабинет. Реальное новое личное подключение Xiaozhi и
физический разговор после него требуют привязки пользователя и ещё не проверены.
Существующие настройки и тома сохранены; SSH закрыт, временные веб-стенды остановлены.
