# План интеграции Studio

1. Добавить хешированное хранилище одноразовых кодов/соединений и HTTP-контракт.
   Проверить изоляцию аккаунтов, Origin/CSRF, expiry, отзыв и сбои записи.
2. Добавить отдельное разрешение владельца на голос pilot и выбор собственного
   устройства через Studio. Проверить committed authorization и отмену сеансов.
3. Реализовать приватный локальный клиент кабинета и форму; публичный поиск,
   чтение SDK и create-only импорт изображений. Проверить инъецированным
   транспортом, не выполняя реальные провайдерские запросы в тестах.
4. Подключить новые инструменты к двум разрешённым файлам установленной Studio,
   сохранив существующие драйверы/проекты. Сделать локальные резервные копии кода,
   не копируя личные данные в публичный репозиторий.
5. Добавить веб-диалог подключения и публичные инструкции. Проверить широкую
   и узкую раскладку, очистку кода и устаревшие ответы при смене сессии.
6. Выполнить node --test и реальные локальные HTTP/browser checks; опубликовать
   только публичный комплект. Сохранить возможность возврата версии сервера.
7. Перезапустить Studio и создать новый проект по обычной идее и референсу.
   Модель сама находит ресурс, читает API, создаёт макет и код. После согласования
   собирает прошивку; физическая установка требует конкретного согласования.

Особый фокус: ключи не попадают в чат/макет/прошивку, Studio-токен не выдаёт права
owner, импорт не перезаписывает драйверы и не переживает смену проекта, личные
настройки не попадают в экспорт/публикацию, старый путь голоса не маскирует ошибки
нового account-pairing пути.
