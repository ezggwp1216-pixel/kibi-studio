# План реализации кабинетов и SDK

**Goal:** регистрация, изоляция данных, одноразовая привязка и доступный комплект SDK.
**Architecture:** шлюз сессий перед отдельными контекстами существующего сервера;
старое хранилище и голос принадлежат владельцу, новые хранилища независимы.
**Tech stack:** Node 24, встроенные crypto/http/fs, русский статический интерфейс.
**Spec:** ../specs/2026-11-09-accounts-pairing-sdk-design.md
**Global constraints:** без npm runtime-зависимостей, приватных данных и запросов
провайдерам в тестах; не трогать рабочий голосовой проект; Git/развёртывание — root.
**Review focus:** межпользовательский доступ, сохранение данных, replay/CSRF,
ограничения нагрузки, честная готовность SDK и голоса.

1. `src/accounts.mjs`, `tests/accounts.test.mjs`: приватный реестр пользователей,
   асинхронные хеши паролей, атомарное сохранение, нормализация почты и лимиты.
2. `src/server.mjs`, `src/pairing.mjs`, `tests/multiuser.test.mjs`: шлюз сессий,
   отдельные контексты, маршрутизация токенов, код привязки, старые вход/голос.
3. `sdk/**`, `examples/**`, `docs/SDK.md`, `docs/LOCAL_STUDIO.md`: контракт и
   валидатор, клиент и инструкция для локальной модели. Никакого исполнения кода.
4. `web/index.html`, `web/app.js`, `web/styles.css`: вход/регистрация/владелец,
   личный кабинет, код привязки и инструкция Studio с копированием.
5. Root обновляет API/развёртывание, запускает node --test, HTTP и браузерные
   проверки, независимый обзор и исправления. Публикация только проверенных файлов;
   серверное обновление с сохранением данных, обратной совместимостью и откатом.

Независимые задачи 1/3/4 выполняются параллельно с фиксированным API и владением
файлами. Это следует текущему разрешению на параллельную работу; агенты не создают
других агентов, не читают приватную Studio и не выполняют Git/развёртывание.
