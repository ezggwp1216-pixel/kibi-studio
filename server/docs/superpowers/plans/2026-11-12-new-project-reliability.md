# New-project reliability repair plan

> **For agentic workers:** Use executing-plans or subagent-driven-development task by task. Root owns integration; assigned agents edit only their named files.

**Goal:** Repair the confirmed fresh-project failures found by the AI inside Studio, using the latest physically verified voice implementation instead of generating another low-level audio stack.

**Architecture:** The portable mockup includes state, input and rendering; hardware lifecycle stays behind the implementation request. Public image import prepares directly renderable bounded pixels. A neutral, reusable Xiaozhi module supplies account pairing and the verified audio/network lifecycle independently of a project's character and layout.

**Tech stack:** Node 24, no runtime npm dependencies; portable C++ and the existing ESP32-S3 device SDK.

**Spec/evidence:** User-authorized Studio audit in the vertical “пудж тренер” project, current API.md/VOICE.md, and explicit permission to inspect only the previous working project's app_core.h, app_feature.h and app_view.h for neutral extraction.

## Global constraints

- Do not read project settings, credentials, history or personalized binaries.
- Do not copy a previous project's character, board identity or unrelated application/test code into the SDK.
- Preserve exact supported hardware adapters, pairing isolation, certificate verification, measured audio settings and honest playback completion semantics.
- No automatic provider call, firmware installation or VPS deployment.
- Updates accept only known public program/SDK hashes; preserve unknown edits and user projects.

## Review focus

- An imported image must render in both native preview and target code without an AI-written PNG decoder.

- Server readiness, compile success and audible speech remain distinct evidence levels.
