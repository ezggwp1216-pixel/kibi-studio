# Обновление публичного SDK Киби

Комплект `2026-11-17-r3` согласует аппаратные инструкции, личный Xiaozhi,
переносимые макеты и известные поколения Wi-Fi. Личные проекты, настройки,
история, авторизация и персональные бинарники не читаются и не заменяются.
Закрытый runtime-код Studio не входит в обновление.

Готовый клиент Xiaozhi устанавливается отдельным проверяемым обновлением
[Studio](LOCAL_STUDIO.md#обновление-существующей-studio). Модель выбирает
`kibi_enable_module({module:"xiaozhi"})` в совместимом проекте. Этот аппаратный
обновлятор не меняет личные проекты и не добавляет клиент в них автоматически.
Канонические исходники клиента включены в `source/` комплекта для проверки.
Добавлен отдельный точный профиль публичной полной Studio из коммита
`43d47afb090c9bf6ab69ea46ee559da3c9867616`: он сохраняет проверенный legacy Wi-Fi,
обновляет звук и вводит защищённый выбор варианта платы. Неизвестные правки
по-прежнему отвергаются; простое добавление их хеша не является обновлением.
Отсутствующий модуль и несовместимость SDK показываются отдельными причинами.

Передайте ИИ после обычного проверяемого запуска Studio:

```text
Обнови публичный SDK моей Киби Studio по актуальной docs/SDK_UPDATE.md
из доверенного корня моей панели с сохранённым префиксом либо официального
https://sldvkibi.ru/server/. Прочитай sdk/device/release.json из того же корня,
скачай указанный архив и проверь SHA-256 до распаковки/запуска.
Используй Node из установленной Studio; Python, Arduino, Homebrew и Xcode
для этого не устанавливай. Studio должна быть закрыта или не занята.
Сначала выполни read-only план update.mjs для выбранной папки Studio.
Не читай .studio, auth.json, настройки, проекты или BIN; managed Node
используй только как исполняемый файл. При известном SDK выполни --apply
с новой резервной папкой вне Studio, затем doctor.mjs. Неизвестный hash
означает остановку с фиксированным кодом, не разрешение обходить проверку.
После успеха открой Studio. Плату не прошивай; спроси, что я хочу создать.
```

Актуальная официальная поставка: `https://sldvkibi.ru/server/`.
На своём сервере сохраняйте его доверенный origin и префикс; инструкцию,
release и архив берите из одного источника, архив проверяйте по SHA-256.
GitHub остаётся источником кода: для воспроизводимой поставки используйте полный
проверенный commit, не подменяйте текущий r2 старым содержимым ветки.
Это дополнение к установщику Studio;
аккаунт Киби для локальной среды не требуется.

На чистом Mac bootstrap уже установил Node:
`<Studio>/.studio/runtime-node/bin/node`. Его запуск не означает чтение приватных
данных `.studio`. Разработчик с Node24 в PATH может использовать обычный `node`.

```sh
"<Studio>/.studio/runtime-node/bin/node" "<kit>/update.mjs" --root "<Studio>"
"<Studio>/.studio/runtime-node/bin/node" "<kit>/update.mjs" --root "<Studio>" --apply --backup-dir "<новая отдельная папка>"
"<Studio>/.studio/runtime-node/bin/node" "<kit>/doctor.mjs" "<Studio>"
```

Без `--apply` изменений нет. До первой записи сверяются известный профиль,
payloads и весь публичный template manifest. Изменённый protected-шаблон,
ссылка или неизвестная версия дают отказ. Нельзя подставлять новый hash в профиль.
При сбое записи обновлённые публичные файлы откатываются. Резервная копия и
receipt содержат только публичный SDK; повторное применение идемпотентно.

`installed-reviewed` сохраняет legacy Wi-Fi/HTTPS. `source-connectivity` относится
к отдельному исходному комплекту с новым controller; им не подменяют работающую
установленную базу целиком. Микрофон есть в обоих вариантах платы.

Doctor проверяет профиль, board snapshots, hashes выбранных публичных заголовков,
подготовку динамика, семейство Wi-Fi и нейтральность инструкции. Его
`hardwareVerified:false` остаётся честным: железо и провайдер не проверяются.
Старые проекты не переписываются; новые возможности принимаются штатным процессом
Studio с проверкой совместимости и новым бинарником. Старый PCM/job helper не
становится совместимым с Opus WebSocket от обновления README.

Разделяйте три проверки голоса: сервер предоставляет личный Xiaozhi своему
кабинету; выбранный проект действительно содержит совместимый клиент и его
зависимости; конкретная сборка прошла проверку на плате и у провайдера. Первая
не подтверждает остальные. `doctor` проверяет выбранные публичные файлы, а не
устанавливает недостающий голосовой клиент. Наличие аудиодрайвера и Opus-кодека
тоже не означает реализацию привязки, TLS/WebSocket и очередности разговора.
После обновления прочитайте фактический API клиентского модуля; при его
отсутствии укажите точный пробел. Не заменяйте рабочий аудиопуть старым helper
по сходству имени.

Актуальный личный путь описан в [VOICE.md](VOICE.md): собственная регистрация
Xiaozhi, своя привязанная Киби и выбор устройства в кабинете. Ошибка не включает
чужого агента или платный OpenAI; пилот владельца требует отдельного одобрения.
Характер переносится в своего агента одним ручным шагом, контекст сервера —
MCP-данные. Изменение этих инструкций само не настраивает провайдера.

На этапе макета общая portable-логика `app_core.h` и рисунок `app_view.h` должны
редактироваться совместно, чтобы зоны касаний соответствовали кнопкам.
Аппаратный lifecycle в `app_feature.h` остаётся за действием «Проект готов»;
оно не даёт разрешение на USB-установку. Совместимость версии Studio проверяется
отдельно: обновление текста не снимает фактические ограничения старой программы.
