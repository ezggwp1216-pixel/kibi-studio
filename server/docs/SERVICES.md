# Как подключать сервисы к приложению Киби

## Четыре разных подключения

| Подключение | Где работает | Какие данные нужны |
| --- | --- | --- |
| ИИ для разработки | Локальная Studio и официальный вход пользователя в ChatGPT | Учётная запись ChatGPT; API-ключ для чата не нужен |
| API внутри приложения | Киби либо выбранный серверный модуль | Только необходимые Wi-Fi/API параметры через защищённые настройки |
| Личный кабинет Kibi Server | Браузер на сайте | Email и отдельный пароль; подтверждение/восстановление почты пока не подключены |
| Привязка устройства | Киби и её собственный кабинет | Короткий код плюс отдельный секрет опроса; индивидуальный токен получает устройство |

Подписка ChatGPT не оплачивает автоматически сторонний API. Сохранённый ключ
или список моделей не подтверждают работоспособность нужной операции. Ключ
разработчика не должен попадать в код, промпт, макет, сериализуемую Model или Git.

## Сначала выберите место работы

**Автономное приложение:** экран, тач, кнопки, таймер и батарея не требуют сети,
кабинета или API. Не запрашивайте Wi-Fi для локального таймера.

**Прямой API:** прошивка отправляет HTTPS-запрос из выделенного worker. Настройки
сохраняются отдельно, при компиляции инжектируются только нужные значения.
Такой бинарник персонализирован и не является публичным файлом для раздачи.
Если сервис позволяет, используйте ограниченный/отзываемый ключ.

**Через Kibi Server:** провайдерские ключи хранятся зашифрованно на сервере;
Киби получает только свой отзываемый device token. Транспорт событий, сообщений,
ack и отдельного текстового ИИ уже реализован. Исполнение загруженного плагина
и расписания пока не реализованы. Голосовой пилот принадлежит владельцу сервера;
обычные кабинеты не получают доступ к его аккаунту Xiaozhi или ключам.

## Совместимость перед кодом

1. Получите текущий SDK/плату/выбранный вариант через реальные kibi-инструменты.
   Сверьте публичные файлы doctor и точные сигнатуры заголовков. Один номер Studio
   не гарантирует одинаковые поколения аудио/Wi-Fi/HTTPS.
2. Уточните операцию: текст, распознавание речи, синтез, потоковый разговор,
   загрузка данных или уведомления. HTTP-совместимость текста не означает
   совместимость аудио или WebSocket.
3. Используйте документацию именно выбранного API и профиля модели. Для OpenAI,
   xAI, Anthropic и Yandex параметры, auth и форматы различаются; профиль в форме
   не переписывает готовое приложение. Не придумывайте endpoint/model/folder ID.
4. Согласуйте управление и состояние: готов, соединяется, слушает, отвечает,
   отменяется, нет сети, ключ отклонён, лимит исчерпан, ответ просрочен.
   Повторное нажатие не создаёт вторую сессию или повторное платное действие.

## Платформа и worker

`Feature::begin` вызывается раньше готовности PM/Wire/ADC2/Wi-Fi. В нём готовят
только portable Model. Платформа уже владеет запуском радио, батареей, вводом,
калибровкой и сном. Worker стартует из первого device tick или принятого действия.
UI loop читает скопированный результат, не ждёт сеть и не трогает чужие ресурсы.

- Legacy SDK: читайте существующие `getJson/postJson` и их параметры в реальном
  `http_json.h`. Не вызывайте отсутствующий `Https::requestJson` по новой статье.
- Controller SDK: `DeviceWifi` разрешает retry/target scan после platform readiness;
  `Accepted` — постановка, `ipReady` — готовность IP. `Https::requestJson` синхронный
  и потому работает только в worker; auth helpers не реализуют протокол провайдера.
- В обоих: конечные таймаут, ответ и очередь; проверка TLS/JSON; отмена поколений;
  ограниченные повторы с паузой. Нельзя отключать TLS или бесконечно повторять
  платный POST. После ошибки сохраняйте последние хорошие данные с признаком stale.

## Микрофон и динамик

Точный жизненный цикл и рецепты приведены в [HARDWARE.md](HARDWARE.md). Микрофон
есть и без динамика. Basic использует MicrophoneI2s/MicrophonePower, speaker —
единственный duplex Session. Нельзя параллельно занять I2S вторым владельцем.
Инициализация усилителя не должна съедать начальные samples; подготовка и guard
не блокируют сеть/ввод. DMA submission и серверный STOP не являются playback ACK.

Старые `realtime_voice_protocol.h`/job helpers используют другой протокол.
Standalone `/kibi-xiaozhi/v1` — Opus16kHz/mono/60ms, hello/version1 и negotiated
features по [VOICE.md](VOICE.md). Эти интерфейсы не взаимозаменяемы.

## Привязка к серверу

Используйте HTTPS-корень панели, например `https://sldvkibi.ru/server/`.
`/api` добавляет клиент; device token нельзя помещать в URL. Киби делает start,
показывает код, пользователь подтверждает в кабинете, Киби опрашивает своим
секретом и забирает токен один раз. После expiry/410 остановите опрос. При потере
финального ответа удалите лишнее устройство и начните новую привязку.

Входящие сообщения обрабатываются идемпотентно и ACK отправляется после обработки.
`eventId` подавляет повторы лишь среди последних200 событий всего кабинета;
устройства делят эту ограниченную историю. Для важных операций нужен свой журнал
обработанных ID и безопасный повтор. Поля и лимиты — в [API.md](API.md).

## Что означает успешная проверка

| Уровень | Что подтверждает | Чего не подтверждает |
| --- | --- | --- |
| Source/SDK doctor | Версии, hashes, API metadata, известные публичные файлы | Работу физической платы |
| Host/native | Model/input/renderer и тестируемые state machines | I2S, радио, зарядку |
| Target | Компиляцию конкретного source/config/SDK под ESP32-S3 | Доступ API, звук, качество тача |
| Server | Авторизацию и реальный контракт сервера с тестовым транспортом | Баланс/доступ внешнего провайдера |
| Device | Конкретные проверенные сценарии на плате | Произвольный будущий код и все роутеры |
| Provider | Явно вызванную операцию с её моделью/ключом | Другую операцию, долгий сеанс или другое устройство |

Тесты по умолчанию используют искусственные данные/transport и не вызывают
платные сервисы. Настоящий тест запускается отдельно и может расходовать API-лимит.
401/403 — настройки/права; 429/quota — лимит; timeout/DNS — сеть или доступность.
ИИ получает фиксированный код и HTTP status; полный ответ провайдера и настроенный
compiler log остаются приватными. Нельзя выдавать смену дизайна за исправление ключа.
