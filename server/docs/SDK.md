# SDK Kibi Server 1.0

Аппаратный слой: [HARDWARE.md](HARDWARE.md), [контракт устройства](../sdk/device/contract.json),
[сервисы](SERVICES.md), [проверяемый пакет обновления](SDK_UPDATE.md).
SDK HTTP-клиента и аппаратный SDK C++ — разные слои. Новый пакет не запускает
плагины и не перепрошивает устройство автоматически.

SDK содержит клиент HTTP API устройства, формат одного файла `.kibiplugin`, JSON Schema, валидатор и примеры. Node 24, без npm-зависимостей. Готовы структурная проверка пакетов и транспорт привязки/событий/сообщений. Установка и безопасное исполнение пользовательского JavaScript пока запланированы. Успешная проверка не означает, что модуль установлен, безопасен или работает.

Полный контракт сервера: [API.md](API.md). Инструкция и мастер-промпт для локальной Studio: [LOCAL_STUDIO.md](LOCAL_STUDIO.md). В своём экземпляре откройте [`/api/sdk`](../api/sdk) для метаданных; пути ниже отсчитываются от корня панели, включая её префикс при установке в подпапке.

## Одноразовая привязка устройства

Серверный адрес — заранее выбранный пользователем HTTPS-корень панели, например `https://kibi.example/server/`, без `/api` на конце. Пример использует несуществующий адрес и не делает запросов до явного вызова метода. Сам клиент ничего не хранит на диске, не выводит в журнал и не запускает платные API.

```js
import { createKibiClient } from './sdk/index.mjs';

const client = createKibiClient({ apiBase: configuredServerBase });
const pairing = await client.startPairing({ name: 'Моя Киби' });
// На экране устройства покажите только pairing.code и срок действия.
// pairing.pollToken хранится в памяти устройства, не в UI/URL/журнале.
// Владелец вводит код в своём кабинете.
// Опрос запускает приложение, не чаще раза в pairing.intervalSeconds.
const result = await client.pollPairing({
  pairingId: pairing.pairingId,
  pollToken: pairing.pollToken,
});
if (result.status === 'paired') {
  await saveDeviceTokenSecurely(result.token); // Реализуйте своим хранилищем.
  client.setDeviceToken(result.token);
  // Очистите секрет опроса. Не печатайте result целиком.
}
```

`configuredServerBase` и `saveDeviceTokenSecurely` — точки интеграции вашего приложения, не предоставленные SDK глобальные функции. В прошивке используйте существующий TLS/HTTP стек платы; JS-клиент не является библиотекой C++ и не подменяет SDK оборудования.

| Запрос | Тело | Успешный ответ |
| --- | --- | --- |
| `POST api/pairing/start` | `{name}` | `201 {pairingId,code,pollToken,expiresAt,intervalSeconds:3}` |
| `POST api/pairing/poll` | `{pairingId,pollToken}` | `200 {status:"pending",expiresAt}` или `{status:"paired",device,token,apiBase}` |
| `POST api/pairing/claim` (только кабинет) | `{code}` | `{ok:true,device}`; токена в ответе владельцу нет |

Код действует пять минут. Подтверждение доступно только вошедшему пользователю с правильными Origin и CSRF. Имя устройства не определяет владельца. После завершения устройство получает токен один раз; повторное получение завершается `410`. Ожидающие привязки сбрасываются при перезапуске сервера; остановите опрос после истечения срока/отмены/`410` и предложите начать заново. Если ответ с токеном потерян в сети, повторный опрос не восстановит его: начните новую привязку, а лишнее устройство удалите в кабинете. SDK не выполняет скрытых повторов и не принимает другой `apiBase` из ответа: origin и префикс пути должны совпасть с настроенным адресом.

Встроенный клиент не содержит браузерного входа и `claim`: подтверждайте код через кабинет. Токен устройства не равен паролю кабинета, ключу OpenAI или Telegram. Храните его в защищённых настройках приложения/платы; не вставляйте его в чат с моделью, пакет, URL, скриншоты и журналы. Не используйте общий токен для нескольких устройств.

## События, сообщения и подтверждения

```js
// Токен загрузите из своего защищённого хранилища, не из строки в коде.
client.setDeviceToken(await loadDeviceTokenSecurely());
await client.sendEvent({
  title: 'Кнопка нажата', message: 'Локальное действие', eventId: 'button:press-42',
});
const { messages } = await client.getMessages();
for (const message of messages) {
  await processMessageIdempotently(message);
  await client.acknowledge({ messageId: message.id });
}
```

Функции загрузки токена и обработки сообщения реализует ваше приложение. `sendEvent` вызывает `POST api/device/events`, `getMessages` — `GET api/device/messages`, `acknowledge` — `POST api/device/ack`; `Authorization: Bearer …` добавляется только к этим маршрутам. Токен не устанавливается автоматически после опроса: сначала сохраните его, затем вызовите `setDeviceToken`. `clearDeviceToken()` убирает его из клиента, но не отзывает на сервере; для отзыва удалите устройство в кабинете.

Заголовок — 1–120 символов, сообщение — 0–2000, необязательный `eventId` — 1–100 символов `A–Z a–z 0–9 _ . : -`. Повтор события использует тот же ID; дедупликация действует отдельно для устройства в пределах последних 200 событий. В очереди до 50 сообщений. Ack отправляется после обработки; потерянный ack может привести к повторной доставке. Для опасных действий храните обработанные ID и обеспечьте повторяемость без повторного эффекта. Частота запросов ограничена сервером; используйте паузы и ограниченные попытки приложения.

Сетевые настройки клиента: `fetchImpl` для внедряемого стандартного Fetch-транспорта, `timeoutMs` от 1 до 60000 (по умолчанию 10000), необязательный `deviceToken`. URL фиксируются при создании клиента; credentials в адресе, query, fragment, неоднозначные сегменты и перенаправления запрещены. TLS проверяется штатным транспортом. При локальном тесте допускается `http://localhost:4391/`, `http://127.0.0.1:4391/` или `http://[::1]:4391/` только с явным `allowLocalhostHttp:true`; для удалённой Киби нужен HTTPS. Ответ ограничен 512 КиБ, время ожидания действует и на чтение тела. SDK не вызывает `api/device/chat`, провайдеров, Telegram и голосовые маршруты. Сам сервер может отправить уведомление о событии в Telegram, если владелец ранее явно включил эту интеграцию; проверяйте события при выключенных внешних интеграциях или с внедрённым тестовым транспортом.

Ошибки — `KibiSdkError` с фиксированными `code`: `invalid_base`, `invalid_argument`, `token_required`, `http_error`, `network_error`, `timeout`, `invalid_response`. При HTTP-отказе есть числовой `status`; тело отказа и текст исключения транспорта не раскрываются. Например, `http_error`/`410` завершает привязку, `401` при работе устройства означает необходимость проверить/заменить токен. Не делайте бесконечных повторов. Публичные поля ошибки можно показывать; объекты привязки/токены — нельзя.

## Пакет `.kibiplugin`

Это один UTF-8 JSON-файл до 128 КиБ; архивы, пути к исполняемым файлам и npm-зависимости не входят в формат. Поля `secrets` допускают только объявления, без значений. Валидатор не распознаёт секрет, ошибочно вставленный в исходник, подпись или обычную настройку: автор пакета обязан исключить его до проверки и передачи файла. Структура версии 1:

```json
{
  "format": "kibi-plugin",
  "manifestVersion": 1,
  "sdkVersion": "1.0",
  "id": "my-event-module",
  "version": "0.1.0",
  "name": "Мой модуль",
  "description": "Что делает модуль и как его проверять",
  "capabilities": ["event-handler"],
  "permissions": ["events:read", "notifications:create"],
  "settings": [{"key":"prefix","label":"Подпись","type":"text","default":"Киби"}],
  "secrets": [{"key":"integrationKey","label":"Ключ интеграции","required":false}],
  "server": {"language":"javascript","source":"export async function onDeviceEvent(event, context) { return { notifications: [] }; }"}
}
```

`id` — стабильный ID до 64 символов из строчных ASCII-букв/цифр с разделителями `.` и `-`, начинается с буквы. `version` — три числовых компонента без ведущих нулей. `name` до 80 символов, `description` до 1000. Неизвестные поля/версии/возможности/разрешения и повторные ключи настроек отвергаются.

`capabilities`: `event-handler`, `message-handler`. `permissions`: `events:read`, `messages:read`, `messages:write`, `notifications:create`. Это объявления будущего контракта, они сейчас не выдают права и не разрешают сетевые запросы/доступ к диску. Пустые списки допустимы.

`settings` — до 16 полей с уникальными `key`, `label`, `type` (`text`, `boolean`, `number`), необязательными `required` и `default` соответствующего типа. `secrets` — до 16 объявлений `{key,label,required}` без `value`/`default`; ключи уникальны также относительно settings. Имена ключей начинаются со строчной буквы, далее ASCII-буквы/цифры/`_`, всего до 48; `constructor`/`prototype` запрещены. Подпись до 120 символов; текстовый default до 2000. Настоящие секреты пользователь вводит только в предназначенной для этого защищённой форме; формы сторонних модулей и их установка пока не реализованы. Не сохраняйте секрет как обычную настройку.

`server` необязателен: `{language:"javascript",source:"…"}`; исходник — непустая строка до 64 КиБ UTF-8. Валидатор проверяет только тип/объём поля, не синтаксис, семантику или безопасность JavaScript. Предлагаемый будущий интерфейс: экспорт `onDeviceEvent(event, context)` для `event-handler` или `onDeviceMessage(message, context)` для `message-handler`, явные настройки в `context.settings`, результат как описание действий. В текущей версии ни один обработчик не вызывается; формат его результата и изолированный исполнитель требуют отдельной реализации и проверки. Не запускайте такие строки через `eval`, `Function`, `import`, `vm` или обычный серверный процесс. Это не готовая песочница.

## Проверка пакета и тесты

Из корня локального комплекта:

```sh
node sdk/validate.mjs examples/server-plugin/local-notification.kibiplugin
node sdk/validate.mjs examples/server-plugin/future-handler.kibiplugin
node --test tests/sdk.test.mjs
node --test
```

CLI выдаёт только `{ok:true,requiresRuntime:false|true,runtimeSupported:false}` либо `{ok:false,errors:[{path,code}]}`, код выхода 0/1. Исходник и содержимое входного файла не печатаются. `requiresRuntime:true` означает, что пакет содержит исходник и для работы нужен ещё не реализованный исполнитель. Пакет без кода тоже не устанавливается.

Из JS: `validatePlugin(jsonText)` из `sdk/index.mjs`; на успехе дополнительно возвращается разобранный `manifest`. Не выводите весь результат в журнал и не исполняйте `manifest.server.source`. Метод принимает только JSON-текст; объект перед ним явно сериализуйте. [JSON Schema](../sdk/kibiplugin.schema.json) полезна редактору; ограничения UTF-8 объёма и уникальность ключей между списками дополнительно проверяет JS-валидатор.

В панели серверная обёртка `POST api/sdk/validate` принимает `{package:<JSON-объект или JSON-текст>}` с сессией, Origin и CSRF. Это только проверка, без установки/исполнения и без внешних запросов. У этого маршрута отдельный лимит тела 136 КиБ, пакет внутри — до 128 КиБ. На остальных маршрутах сохраняется 16 КиБ. Для крупных пакетов также доступна локальная CLI-проверка.

Тесты SDK используют внедрённый транспорт и искусственные секреты, без внешней сети и платных вызовов. Пройдённый локальный тест не подтверждает развёртывание на VPS, доступ к провайдеру, прошивку или физическую работу Киби. Новая привязка требует совместимой прошивки: старый бинарник не начнёт показывать код и опрашивать API автоматически. Голос имеет отдельный контракт и реальные состояния; многопользовательский голос и расписания здесь не готовы.
