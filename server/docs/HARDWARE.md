# Аппаратный контракт Киби 1.0

Этот контракт помогает разработать приложение на штатной базе Киби DS-02. Киби имеет экран, тач, две кнопки, Wi-Fi, микрофон и поддержку аккумулятора; динамик зависит от выбранного варианта. Наличие аппаратного слоя не означает, что новое приложение уже подключило его или прошло проверку на плате. Машиночитаемая версия — [sdk/device/contract.json](../sdk/device/contract.json). Сервер необязателен для автономного приложения; его отдельный контракт — [API.md](API.md), голос — [VOICE.md](VOICE.md).

Контракт описывает публичные исходники. Проверка исходников, host-тест, целевая сборка, тест на устройстве и проверка внешнего сервиса — разные свидетельства. Здесь не объявляются новые физические результаты, удачная сборка конкретного приложения или доступ к провайдеру. Перед изменением сохраните рабочую версию штатным способом Studio; не читайте персональные проекты и защищённые настройки ради примера.

## Профиль и совместимость снимков

| Параметр | Значение |
| --- | --- |
| Плата | `kibi-ds02-s3-16m`, ESP32-S3 |
| SDK | Arduino ESP32 **3.3.12** как компонент ESP-IDF **5.5.5** |
| Память/flash | 16 MiB flash, DIO 40 MHz; OPI PSRAM 80 MHz; слот приложения 2 097 152 байта |
| Экран | 240×296, RGB565, радиус видимой маски 62 px |
| Кнопки | Справа сверху вниз: `plus`, питание, `minus`; GPIO40 и GPIO39 active LOW. Питание не является третьим обычным GPIO-вводом приложения. |
| Аудио | I²C SDA12/SCL11; ES7210 `0x40`, ES8311 `0x18`; MCLK5/BCLK15/WS16/DIN7/DOUT6; усилитель GPIO4 active HIGH |
| Варианты | `basic` — без динамика; `speaker` — с динамиком. Микрофон есть в базовой платформе обоих вариантов. |

Обязательны штатные настройки PM, tickless idle, `CONFIG_I2S_ISR_IRAM_SAFE`, OPI PSRAM и полный TLS certificate bundle из `board.json`. Не заменяйте SDK, таблицу разделов, драйверы или зависимости по предположению. Именно ESP-IDF5.5.5 предоставляет поле `i2s_chan_info_t::mclk_hz`, используемое микрофонным драйвером; произвольный более старый 5.x не является совместимой заменой. Связь версий подтверждена [релизом Espressif](https://github.com/espressif/arduino-esp32/releases/tag/3.3.12), API — [заголовком I²S5.5.5](https://github.com/espressif/esp-idf/blob/v5.5.5/components/esp_driver_i2s/include/driver/i2s_common.h).

Номер приложения Studio сам по себе не определяет весь SDK. При аудите обнаружены два **смешанных** публичных снимка:

| Семейство | Проверенный снимок исходников | Проверенный установленный снимок |
| --- | --- | --- |
| Аудио | `audio_codec_power.h` без `preparePlayback()` | Тот же базовый драйвер с `preparePlayback()` и состоянием подготовки |
| Wi-Fi | `DeviceWifi::snapshot/requestRetry/requestTargetScan/scanSnapshot/cancelTargetScan` | Старый контракт `beginWifi`; новые методы не объявлены его метаданными |
| HTTPS | Новые метаданные `Tamagotchi::Https`, ограниченные GET/JSON POST | Другая версия заголовка; нельзя переносить новый интерфейс без проверки |
| Mic/filter/legacy voice/audio file | Совпали побайтно | Совпали побайтно |

Это результаты сравнения до согласования поставки, а не предложение выбрать один снимок целиком. Сверяйте manifest, `board.json`, реальный заголовок и доступные символы каждой подсистемы. `preparePlayback()` разрешён только в снимке, где он действительно есть; новый `DeviceWifi` нельзя вызывать в старой установленной базе. Обновление документации не обновляет уже созданный проект, удалённый компилятор или прошитый бинарник. Не редактируйте protected-файлы из приложения; согласованный снимок принимает штатный механизм Studio/сборки.

## Запуск и владельцы ресурсов

Приложение реализует только штатные точки расширения:

```cpp
// app_feature.h, namespace KibiApp::Feature
void begin(Model&, View::Context&);
bool tick(Model&, View::Context&, uint32_t now);
void input(Model&, const Input&, Action);
```

`Feature::begin` приложения вызывается **до** защищённой подготовки платформы. В нём готовьте модель и состояние; не запускайте Wi-Fi, I²S, задачи, которым нужны готовые PM/LCD/Wire, и не вызывайте platform boot hooks. Защищённая база инициализирует PM/дисплей, измеряет ADC2 батареи и только затем запускает Wi-Fi. Аппаратный worker начинает работу после этой подготовки; `Feature::tick` вызывается после неё. Отдельно проверьте результат `begin()` своего модуля: порядок вызова сам по себе не доказывает его готовность.

Основной цикл обрабатывает ввод, обновляет модель и рисует. Сеть, запись файлов и аудио обслуживаются ограниченными workers. У каждого аудиоресурса один владелец; команды UI проходят через ограниченную очередь/снимок состояния. Только владелец выполняет `begin/read/write/stop/end`; другой task не закрывает Session во время I/O. Не вызывайте callbacks UI или отрисовку из ISR. При отмене помечайте поколение устаревшим и убирайте его очередь, чтобы поздний сетевой ответ не возобновлял старую операцию.

Аудиовладелец после готовности PM удерживает `Tamagotchi::PowerManagement::PerformanceLease` из `power_management.h`; проверяет `held()` и освобождает lease при завершении. Счётчики ISR и объект Session должны быть во внутренней RAM; размещать весь Session в PSRAM нельзя. Большие разрешённые буферы могут жить в PSRAM отдельно от ISR-состояния. Успех выделения памяти, стека и запуска задачи проверяется, а не предполагается.

## Дисплей и типографика

Публичная точка рисунка — `KibiApp::View::render(uint16_t* pixels, size_t count, const Model&, const Context&)`. Платформа передаёт framebuffer, сама вызывает `prepareDisplayFrame(0)`/`presentDisplayFrame()` и управляет сном дисплея. Приложение рисует только в переданные границы, не создаёт второго владельца LCD/SPI и не меняет ориентацию, GPIO или touch calibration. Для полного кадра нужно 71 040 пикселей, 142 080 байт; `count` всегда проверяется.

`View::Context` содержит `nowMs`, `online`, `loading`, `stale`; `online=true` в нейтральной заготовке — сценарное значение, **не результат проверки Wi-Fi**. Настоящие состояния проецируются из аппаратного снимка в модель. Preview проверяет общий renderer/модель и не эмулирует LCD, I²C, радиосвязь, батарею или звук.

Используйте подготовленный Source Sans3 из `kibi_typography.h`; это шрифт устройства, отдельный от Manrope веб-панели. Рисование — в native RGB565, координаты/clip в пикселях, `stride` в пикселях. Не увеличивайте старую bitmap-маску для крупных цифр; выбирайте готовый размер по фактическим метрикам и переносите строки явно. Сохраняйте OFL и исходную лицензию.

## Тач и кнопки

Точки ввода приложения определены в `app_core.h`: `KibiApp::InputKind {Plus, Minus, Tap, Swipe}` и `Input {kind, x, y, dx, dy, durationMs}`. `reduceInput(Model&, const Input&)` возвращает `Action {None, NextScreen, PreviousScreen, OpenModule, CloseModule, Toggle}`. Защищённый адаптер сначала вызывает reducer, затем `Feature::input`; обработчик `input` не отменяет уже выполненный переход. Изменяйте разрешённый reducer для своей логики, сохраняйте сигнатуры. Несуществующего `Feature::buttonPress` в этом контракте нет.

GPIO40/39 опрашиваются как active LOW с debounce35 мс; приложение получает одно событие на нажатие, а не поток release/long-hold. Не обещайте длительное удержание без отдельной реализованной модели событий. Тач CST810 даёт низкоуровневые `Down/Move/Up/Cancel`; ими владеет адаптер, приложение получает `Tap/Swipe` на отпускании. `Cancel` отменяет жест. Tap требует смещения не более10 px и того же `hitTarget`; стандартный горизонтальный swipe — не менее28 px, больше вертикального смещения, длительность не более1200 мс. При своей обработке используйте переданные координаты, `dx/dy/durationMs`; не читайте CST810 второй задачей.

Проверка: оба фронта физических нажатий с дребезгом; касание внутри/снаружи цели; уход за её границу; отмена; быстрый и медленный свайп; сон/пробуждение. Preview доказывает переходы модели, а физическая проверка — реальные кнопки/тач.

## Аккумулятор и питание

Защищённый `state_info.h` содержит `Tamagotchi::StateInfoDetail::runtime.info`: `hour/minute`, `wifiLevel`, `batteryPercent`, `chargingKnown`, `charging`, `chargingStep`. `batteryPercent=-1` означает неизвестное/устаревшее показание; до первого измерения зарядки `chargingKnown=false`. Проецируйте нужные поля в свою модель в `Feature::tick` под `#ifdef ARDUINO`; не используйте этот аппаратный namespace в native renderer и не выдавайте сценарное значение preview за измерение.

Батарея читается на GPIO17/ADC2, 12 бит, `ADC_11db`; первичная серия16 отсчётов с интервалами2 мс выполняется **до Wi-Fi**. Raw — отсчёты ADC, не милливольты. Приближённая шкала raw→%: `1985→0`, `2048→20`, `2172→40`, `2296→60`, `2420→80`, `2482→100`, с интерполяцией/ограничением. Серия отвергается, если любой отсчёт `<64` или `>4031`; принятая средняя сглаживается `(3×старое+новое)/4`. Последнее корректное значение сохраняется до30 с, затем процент снова неизвестен. Не показывайте неизвестное как0% и не называйте эту шкалу измерителем ёмкости или напряжения.

Обновление состояния — примерно2 с при включённом экране и15 с при выключенном; сбор серии пошаговый. Зарядка опрашивается примерно100 мс: GPIO47 LOW сразу означает активную зарядку; состояние снимается после3 с без LOW. Визуальная «полная батарея» в старом UI начинается выше85% и не равна измеренным100%. Сохраняйте штатные сон/пробуждение, NVS, ADC-порядок и обработку кнопки питания; аппаратная схема зарядки и её индикация не проверяются host-тестом.

## Wi-Fi, время и HTTPS

Новый публичный контроллер — `Tamagotchi::DeviceWifi` из `wifi.h`: `snapshot()`, `tick(uint32_t)`, `requestRetry(uint32_t)`, `requestTargetScan(uint32_t)`, `scanSnapshot()`, `cancelTargetScan()`. `beginAfterPlatformReady()` — только платформе, один штатный запуск после ADC2. Приложение не вызывает `WiFi.begin`, не меняет режим/credentials/AutoReconnect, не сканирует все сети и не выводит SSID/BSSID/пароль. Принятый запрос retry/scan означает постановку в очередь; результат читается позже. Только `ipReady` разрешает Интернет-запросы. В старом установленном снимке этих API нет: не эмулируйте их guessed-wrapper и не копируйте новый вызов в старую базу.

Время синхронизируется NTP в прошивке; preview-время не доказывает NTP на устройстве. До корректного времени сохраняйте состояние синхронизации, не отключайте TLS ради получения данных. Для нового снимка `Tamagotchi::Https::requestJson` из `http_json.h` предоставляет ограниченные HTTPS GET/JSON POST. Ограничения: запрос до262 144 байт, ответ до16 384 байт, срок по умолчанию20 с; перенаправлений и скрытых повторов нет. `bearerAuth`, `apiKeyAuth`, `anthropicAuth` только формируют авторизацию и не реализуют протокол провайдера. Проверьте точную сигнатуру установленного заголовка перед кодом; старый HTTPS-заголовок не объявляется совместимым этой таблицей.

Блокирующее HTTPS выполняется только worker под `#ifdef ARDUINO`, с конечным сроком/размером/числом попыток. UI и аудиозахват продолжаются во время запроса. При offline/timeout сохраняйте последнюю корректную информацию с явным возрастом; loading не должен превращаться в фиктивный успех. Не начинайте новый запрос в каждом tick. Отдельно проверяйте восстановление после отказа старта/остановки radio; его нельзя выводить из успешного первого подключения. Тесты транспорта внедряются без реального провайдера и сообщений.

## Микрофон без динамика

Отсутствие динамика не означает отсутствие микрофона. `DeviceAudio::Session` — duplex-интерфейс, целиком заблокированный без `KIBI_DEVICE_HAS_SPEAKER==1`, включая его `readMicMono`. Для mic-only используйте существующие `MicrophoneI2s::StandardDriver`, `MicrophoneI2s::Capture<Driver>`, `MicrophonePower::Codecs<Bus>` и `MicrophonePower::Lifecycle<Capture, Codec>` из `microphone_i2s.h`/`audio_codec_power.h`.

Порядок одного владельца: подготовить уже инициализированный общий Wire bus, acquire/wake через Lifecycle, запустить I²S master RX на порту0, выдержать предусмотренный **самим Lifecycle** preroll80 мс при работающем MCLK, затем штатно инициализировать ES7210. Общий wake-бюджет600 мс включает preroll и I²C с существующим timeout20 мс; повторная подготовка не обходит ошибку предыдущей очистки. Не меняйте shared Wire clock/timeout и регистры ADC по совету модели. Codec использует сохранённую stereo/bias/30 dB последовательность `kInitializeAdc`.

Захват — stereo PCM16 16 кГц Philips, MCLK×256, DMA8×512 stereo frames (16 384 байта payload плюс служебная память). `Capture::read(stereo, capacityFrames, frames, timeoutMs)` принимает ёмкость в **stereo frames**, не байтах/mono samples. На кадр нужно два `int16_t`; количество обработанных кадров берите из `frames`, включая выровненный частичный результат при `TimedOut`. Один worker читает ограниченными порциями; ISR меняет только внутренние DRAM-счётчики. Не пишите файл/сеть и не выделяйте память в ISR.

В конце/при отмене всегда выполняйте `Lifecycle::standby()`: сначала ADC/analog/bias standby при доступном MCLK, затем `Capture::end()` с удалением канала; простой `stop()` оставляет жизненный цикл неполным. Проверяйте результат очистки; `StandbyScope` может быть RAII-страховкой, но явный close нужен для сообщения об ошибке до объявления успеха. Перед новым захватом сбрасывайте собственный `MicrophoneAudio::VoiceFilter`; его коэффициенты рассчитаны строго на16 кГц. Фильтр не является AEC и не включается автоматически в duplex-read.

## Микрофон и динамик одним владельцем

Для варианта `speaker` используйте один `Tamagotchi::DeviceAudio::Session` из `audio_codec_power.h` после штатной инициализации дисплея/Wire/PM. Не запускайте одновременно отдельный `MicrophoneI2s::Capture`. `begin()` получает эксклюзивный lease, создаёт RX/TX на I²S0, запускает clocks, ждёт штатные80 мс, проверяет оба codec и выполняет их сохранённые последовательности; это подготовка worker, а не неблокирующий UI-вызов. DAC reset содержит дополнительную штатную паузу20 мс. ES8311 register0x32=`0xBF` означает0 dB; не заменяйте на `0xFF`.

Аппаратный поток — PCM16 stereo16 кГц/MCLK×256. `readMicMono` берёт первый stereo slot; `writeSpeakerMono` масштабирует mono и дублирует его в оба slot. DMA4×128 stereo frames на направление:2048 байт RX и2048 байт TX плюс служебная память. Каждая операция принимает1–256 mono samples и не более20 мс ожидания, даже если запрошено больше. По умолчанию громкость20%, допустимы0–100. RX timeout может вернуть полезный частичный результат и не сбрасывает TX; TX timeout/error останавливает playback. Не продолжайте полный ACK после такой ошибки.

Ниже — только порция захвата из уже запущенного Session в его единственном worker. `audio` и `mono` объявлены здесь, `begin()`/lease/передача данных и завершение принадлежат жизненному циклу приложения, а не UI renderer:

```cpp
#ifdef ARDUINO
#include "audio_codec_power.h"
static Tamagotchi::DeviceAudio::Session audio;  // internal RAM, не PSRAM

Tamagotchi::DeviceAudio::Status readOneChunk(int16_t (&mono)[256], size_t& got) {
  // Вызывать только владельцу после успешного audio.begin().
  return audio.readMicMono(mono, 256, got, 0);
}
#endif
```

Для записи PCM используйте `writeSpeakerMono(source, count, submitted, timeoutMs)` с сохранением ещё не переданных samples. Готовность источника, decoder, программной очереди и DMA — отдельные состояния. `stopPlayback()` выключает amp, очищает весь TX DMA и снова запускает TX clock; это отмена/terminal cleanup, а не функция дождаться хвоста. `end()` отключает amp, переводит ADC/DAC в standby при MCLK, закрывает каналы и освобождает lease; при сбое сохраните ошибку и повторите допустимую очистку перед новым begin.

## Подготовка усилителя и завершение воспроизведения

В снимке с методом `bool Session::preparePlayback()` он допустим только после успешного begin, при ненулевой громкости и из того же worker с PerformanceLease. Он включает усилитель без PCM, ожидания и изменения `playing()`. Повторный вызов не перезапускает подготовку. Нулевой PCM сохраняет её; первый ненулевой после scaling sample переводит в прежнее playing-состояние. Mute/stop/end/TX error снимают подготовку; после unmute нужен новый явный вызов.

Если конкретная плата требует измеренный интервал установки усилителя, храните дедлайн в состоянии worker: во время guard продолжайте RX/сеть, удерживайте **все** media samples и проверяйте cancel/mute/generation. Длительность guard этот контракт не назначает. Не вставляйте блокирующий `delay()` перед каждым chunk, не съедайте начало аудио и не меняйте codec/DMA/библиотеку Opus ради этой подготовки. Успех метода не подтверждает аналоговую готовность, звучание или ACK.

**`writeSpeakerMono()==Ok` подтверждает копирование PCM в DMA, а не слышимость.** `playing()` тоже не является аппаратным completion fence. В публичном Session нет API TX completion: пример выше не добавляет его. Не вызывайте stop сразу после последнего write, если требуется сохранить хвост; не выдумывайте drain через `delay(32)` или число принятых samples. Требуется отдельное проверенное аппаратное свидетельство завершения для выбранного приложения. Значение «передано столько-то» нельзя послать как «проиграно столько-то».

Для standalone Xiaozhi при невозможности доказать полный playout допустим `playback_resolution` со `state:"rejected"` **только** после feature detection, matching обычного `tts/stop` и terminal local cleanup decoder/очереди/DMA. Это отказ от доказательства полного воспроизведения, не ACK и не утверждение, что звук услышан. Для OpenAI такое событие не поддерживается. Точные идентификаторы, гонка STOP и ограничения — в [VOICE.md](VOICE.md). Не добавляйте этот control по имени старому PCM/job соединению.

## Файлы, протоколы и сервер

`audio_file.h` содержит ограниченный WAV recorder и recovery одного pending recording: PCM16 mono16 кГц, предел из `kAudioMaxSeconds` конфигурации. Он не воспроизводит звук и не подменяет сетевой протокол. `BoundedText` использует PSRAM и не откатывается к internal DRAM при нехватке памяти. Файловые `append/finish/recovery/fsync` выполняются worker; сохранение и потребление записи — отдельные подтверждённые шаги. Не форматируйте filesystem и не стирайте NVS/Wi-Fi/чужие данные при сетевой ошибке или новой привязке.

| Протокол | Реальные сообщения | Совместимость |
| --- | --- | --- |
| Legacy CloudVoice/RealtimeVoice | `job_id`, ready/transcript/preview/command; protocol2; PCM ring1 MiB, PCM frame≤4096 байт | Это существующие legacy helpers, не standalone Opus voice и не публичный контракт нового server. Не подключать по совпадению имени. |
| Kibi Server HTTP | Одноразовая pairing, Bearer device events/messages/ack/chat | [API.md](API.md); для C++ реализовать штатным TLS/HTTP стеком, JS `.mjs` не вставлять в прошивку. |
| Kibi Server voice | TLS WebSocket `/kibi-xiaozhi/v1`, hello version1; Opus mono16 кГц,60 мс,≤1275 байт | Требует отдельного совместимого приложения/codec. PCM legacy helper не является реализацией. |
| OpenAI text | Stateless `POST api/device/chat` | Не streaming voice и не сохранённый разговор. Ключ хранится на server. |

Серверный адрес выбирает пользователь заранее: HTTPS origin+prefix. Pairing показывает только короткий code; `pollToken` — отдельный секрет в RAM. Индивидуальный token хранится штатно, не в коде/URL/журнале. Не следуйте redirect с Bearer и не принимайте новый origin из ответа. Offline автономное приложение сохраняет работу. Сеть/провайдер не запускаются автоматически при открытии страницы, сохранении настройки или тестах. Расписания, выполнение `.kibiplugin`, многопользовательский voice и BLE в текущем SDK не объявляются готовыми; ESP32-S3 не поддерживает Classic/SPP/A2DP.

## Повторяемая проверка приложения

1. Зафиксировать публичный manifest/hash, board profile, variant и список **нужных** функций. Проверить наличие каждого символа по заголовку/контракту. Не заменять рабочий SDK и не переносить старую README другого приложения.
2. Host: модель/reducer/renderer, размеры framebuffer, debounce/жесты, неизвестная батарея, stale/offline/loading, wraparound времени, cancel/generation и конечные очереди. Транспорт — внедрённый; реальные ключи и внешние сообщения не нужны.
3. Target: сборка точным Arduino3.3.12/IDF5.5.5, slot≤2 MiB; DRAM/PSRAM/stack, IRAM callbacks и необходимые sdkconfig. Успешный native preview не заменяет target build.
4. На выбранной плате после явной прошивки: экран/маска, обе кнопки, tap/swipe/cancel, реальное Wi-Fi и восстановление, батарея unknown/valid/stale/charging, сон/пробуждение. Для mic — два последовательных захвата и отмена, для speaker — начало/хвост/тишина/volume/mute/cancel и два последовательных ответа с честным completion.
5. Server: отдельные pairing/event/дубликат/message/ack/restart/revoke проверки с выключенными внешними интеграциями. Provider: отдельный явный тест. Listener/hello/сетевой write не заменяют физическое аудио.
6. Отчёт отдельно по уровням `source`, `host`, `target`, `device`, `provider`: версия/артефакт, что выполнено и результат. После диагностической прошивки вернуть последнюю согласованную рабочую версию штатным способом, проверить её запуск и сохранить этот результат. Не читать персональный BIN/проект для восстановления.

Повторите регрессии после изменения SDK: cleanup/retry после частичного init; многократные begin/end; несовместимые владельцы; mic timeout без сброса TX; guard с нулевым PCM; mute/cancel во время guard; позднее старое поколение; неполная запись; окончание источника при непустом DMA; протокольные несовпадения; radio Stopped/start failure. Отсутствие ошибки в одном счастливом проходе не закрывает эти состояния.

Исходные точки проверки: `templates/kibi-base/board.json`, `manifest.json`, `firmware/{microphone_i2s.h,microphone_filter.h,audio_codec_power.h,audio_file.h,cloud_voice_protocol.h,realtime_voice_protocol.h,realtime_voice_messages.h}`; input/power/network API описаны относительно публичного дерева `firmware`. Сброс очередей/курсорa и preload подтверждены [драйвером Espressif5.5.5](https://github.com/espressif/esp-idf/blob/v5.5.5/components/esp_driver_i2s/i2s_common.c). Эти ссылки подтверждают программную семантику, а не физический результат на Киби.
