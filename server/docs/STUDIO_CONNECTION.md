# Кабинет → Studio → Киби

1. Зарегистрируйтесь по email в Kibi Server. Откроется ваш пустой кабинет
   и одноразовый код подключения Studio. Email-подтверждение и восстановление
   пароля пока не настроены; регистрация не подтверждает владение адресом.
2. В локальной Studio нажмите **Аккаунт**, вставьте код и задайте название
   компьютера. Код действует 10 минут и используется один раз. Для повторной
   попытки в кабинете нажмите **Подключить Studio → Получить новый код**.
3. Опишите приложение в чате Studio и приложите ссылку/фото референса.
   Модель читает реальный SDK, ищет публичные ресурсы, создаёт макет и обсуждает
   управление. Настройки Wi-Fi/API вводите в предназначенных формах.
4. После согласования нажмите **Проект готов**. Модель создаст и проверит код;
   компилятор сервера соберёт прошивку. Локально не нужны Arduino IDE и библиотеки.
5. Установите прошивку на свою Киби обычным действием Studio. Приложение с
   поддержкой привязки покажет короткий код устройства. Введите его в
   **Аккаунт → Привязать Киби**. Только плата, ожидающая результат своей
   привязки, получит собственный токен. Регистрация не меняет старую прошивку.
6. Для собственного голоса откройте в кабинете сервера **Модули → Голосовой ИИ →
   Мой аккаунт Xiaozhi**. Нажмите **Получить код** и оставьте панель открытой:
   начнётся ограниченная автопроверка активации. В соседней вкладке добавьте
   устройство на официальном сайте Xiaozhi и настройте агента с этим устройством.
   После подтверждения вернитесь в панель; ручная **Проверить привязку** доступна
   для немедленной проверки без второго параллельного запроса. Затем выберите
   свою Киби здесь или в Studio кнопкой **Подключить голос**. Одобрение общего
   пилота владельца для личного подключения не требуется; пароль Xiaozhi
   вводится только на его официальном сайте.
7. В **Аккаунт → Помощник Киби** выберите устройство, нажмите **Загрузить профиль**,
   задайте характер, контекст и разрешённые действия, затем сохраните профиль.
   Модель Studio использует `kibi_get_assistant` и `kibi_set_assistant` с вашим
   устройством; она должна согласовать эти данные с вами.
8. Нажмите **Скопировать роль** и вручную вставьте текст в своего агента Xiaozhi.
   Повторите этот шаг после изменения характера. Сохранение в Studio само по
   себе не применяет системную инструкцию в облаке. Проверьте статус подключения,
   использование контекста и разговор на своей плате отдельно.

Подключение Studio действует 90 дней. Его можно отозвать в кабинете, где видны
название компьютера и срок действия. Устройство и Studio имеют разные ключи:
отзыв Studio не отключает уже привязанную Киби. Для отключения платы удалите
её из кабинета. В автономных проектах вход в кабинет не обязателен.

Новые подключения Studio получают семь прав: `pairing.claim`, `devices.list`,
`voice.status`, `voice.activate`, `catalog.read`, `assistant.read`, `assistant.write`.
Старое подключение с пятью правами продолжает работать в своих прежних границах;
для профиля помощника создайте в кабинете новый код и переподключите Studio.
Права не расширяются молча.

## Что получает модель

Безопасный статус кабинета, список ваших устройств, доступность голоса,
публичные инструкции и исходники активного проекта. С новыми правами она также
читает и сохраняет согласованный профиль помощника вашей Киби. Пароль, StudioToken,
ключи провайдеров и токен устройства ей не передаются. Одноразовый код Studio
вводится в форму и хранится на сервере только в виде хеша; постоянный токен
Studio — в закрытом локальном файле с правами 0600.

## Что делает помощник

Характер — до 4000 символов, контекст — до 6000. Профиль хранится зашифрованно
на сервере отдельно для своей Киби; сохранение увеличивает его версию. Не
помещайте пароли, ключи или токены в характер и контекст: это данные, которые
может прочитать модель. Автоматической памяти бесед нет.

При личном голосовом подключении MCP-инструмент `kibi.get_context` возвращает
текущий профиль как данные, а не новую системную инструкцию. Модель облака сама
решает, вызвать ли инструмент; одно сохранение не доказывает, что она его
прочитала. По вашему разрешению доступны два дополнительных действия:

- `kibi.get_device_status` — сохранённые имя, состояние связи и время последнего
  запроса своей Киби. Заряд и физическое состояние этим не измеряются.
- `kibi.notify` — постановка уведомления в существующую очередь своей Киби.
  Это не подтверждение доставки или показа на экране.

Громкость, яркость, лица и таймер не являются готовыми серверными действиями.
Произвольные скрипты и URL облако не исполняет. Список действий ограничен
встроенным каталогом и вашим текущим разрешением.

## Ресурсы и дизайны

Модель может искать публичные GitHub-репозитории и читать HTTPS-референсы.
Страницы рассматриваются как внешние данные, их скрипты не запускаются.
PNG/GIF/BMP добавляются проверенными блоками в существующее хранилище изображений;
штатная основа сохраняется побайтно, драйверы не меняются. Новые файлы прошивки
для каждого изображения не создаются. Для известных ресурсов используется рецепт
с SHA256. Неизвестная лицензия не превращается в разрешение на распространение.
Публичный серверный пакет содержит метаданные рецепта, а не чужие bitmap-данные.

## Границы первой версии

Один общий TLS-шлюз допускает до четырёх разговоров: один на личную регистрацию
кабинета и один на сохранённое подключение владельца/пилота. Общий Xiaozhi pilot
по-прежнему требует отдельного одобрения одного кабинета и выбора его устройства;
его ключи не выдаются пользователям. Личная настройка и её ошибки не переключают
вас на этот пилот. Отключение своего Xiaozhi завершает только собственный разговор
и требует новой привязки; личный режим сохраняется. Платный OpenAI автоматически
не включается. Пользовательские
плагины пока проходят проверку манифеста; запуск произвольного загруженного кода
сервером не реализован. Успешная компиляция, превью или статус «ожидает устройство»
не заменяют физическую проверку микрофона, тача и динамика.
