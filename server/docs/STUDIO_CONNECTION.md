# Кабинет → Studio → Киби

1. Зарегистрируйтесь по email в Kibi Server. Откроется ваш пустой кабинет
   и одноразовый код подключения Studio. Email-подтверждение и восстановление
   пароля пока не настроены; регистрация не подтверждает владение адресом.
2. В локальной Studio нажмите **Аккаунт**, вставьте код и задайте название
   компьютера. Код действует 10 минут и используется один раз. Для повторной
   попытки в кабинете нажмите **Подключить Studio → Получить новый код**.
3. Опишите приложение в чате Studio и приложите ссылку/фото референса.
   Модель читает реальный SDK, ищет публичные ресурсы, создаёт макет и обсуждает
   управление. Настройки Wi-Fi/API вводите в предназначенных формах.
4. После согласования нажмите **Проект готов**. Модель создаст и проверит код;
   компилятор сервера соберёт прошивку. Локально не нужны Arduino IDE и библиотеки.
5. Установите прошивку на свою Киби обычным действием Studio. Приложение с
   поддержкой привязки покажет короткий код устройства. Введите его в
   **Аккаунт → Привязать Киби**. Только плата, ожидающая результат своей
   привязки, получит собственный токен. Регистрация не меняет старую прошивку.
6. Для голоса выберите эту Киби в списке и нажмите **Подключить голос**.
   Это доступно только если владелец сервера разрешил вашему кабинету личный
   Xiaozhi pilot и завершил настройку провайдера. Подключение проверяется по
   фактическому статусу, затем — разговором на плате.

Подключение Studio действует 90 дней. Его можно отозвать в кабинете, где видны
название компьютера и срок действия. Устройство и Studio имеют разные ключи:
отзыв Studio не отключает уже привязанную Киби. Для отключения платы удалите
её из кабинета. В автономных проектах вход в кабинет не обязателен.

## Что получает модель

Только безопасный статус кабинета, список ваших устройств, доступность голоса,
публичные инструкции и исходники активного проекта. Пароль, StudioToken,
ключи провайдеров и токен устройства ей не передаются. Одноразовый код Studio
вводится в форму и хранится на сервере только в виде хеша; постоянный токен
Studio — в закрытом локальном файле с правами 0600.

## Ресурсы и дизайны

Модель может искать публичные GitHub-репозитории и читать HTTPS-референсы.
Страницы рассматриваются как внешние данные, их скрипты не запускаются.
PNG/GIF/BMP добавляются проверенными блоками в существующее хранилище изображений;
штатная основа сохраняется побайтно, драйверы не меняются. Новые файлы прошивки
для каждого изображения не создаются. Для известных ресурсов используется рецепт
с SHA256. Неизвестная лицензия не превращается в разрешение на распространение.
Публичный серверный пакет содержит метаданные рецепта, а не чужие bitmap-данные.

## Границы первой версии

Общий Xiaozhi pilot — один одобренный кабинет, выбранное устройство и один
активный разговор. Платный OpenAI автоматически не включается. Пользовательские
плагины пока проходят проверку манифеста; запуск произвольного загруженного кода
сервером не реализован. Успешная компиляция, превью или статус «ожидает устройство»
не заменяют физическую проверку микрофона, тача и динамика.
