01

ИИ · характер Киби

Загружаем

Подключите OpenAI и задайте инструкции: как Киби отвечает, что знает и какой у неё характер. Текстовая проверка работает без памяти диалога. В режиме OpenAI характер применяется и к голосу собственных устройств. Для Xiaozhi инструкции задаются в его консоли; голосовой шлюз включается отдельно.

Ключ шифруется на сервере и не возвращается в браузер. Оставьте поле пустым, чтобы сохранить существующий ключ.

По умолчанию gpt-5-mini. Укажите точное имя доступной вам модели OpenAI.

До 4000 символов. Не помещайте пароли и ключи в инструкции.

Проверить ответ

Явная отправка запроса в OpenAI с сохранённой моделью и инструкциями. Запрос может расходовать баланс вашего аккаунта.

02

Уведомления

Загружаем

Принимает события устройств, хранит ленту и очередь сообщений для каждой Киби. Устройство забирает сообщения и подтверждает получение.

03

Telegram

Загружаем

События сервера приходят в ваш чат. Секреты шифруются на диске и не возвращаются в панель.

Для первого подключения заполните оба поля. Если ключи уже сохранены, оставьте поля пустыми, чтобы сохранить их.

«Отправить проверку» отправит реальное сообщение бота в сохранённый чат. Изменения в форме начнут действовать после сохранения.

04

Голосовой ИИ

Загружаем

Живой разговор через ваш сервер: Xiaozhi или OpenAI. Одновременно работает один разговор. Провайдер выбирается явно.

Получаем состояние голосового шлюза…

Провайдер голоса

Один аккаунт Xiaozhi доступен только выбранному проекту. При сбое платный OpenAI автоматически не включается.

Привязка Xiaozhi

Не подключён

Открыть Xiaozhi ↗

Получите код, добавьте устройство в своём аккаунте Xiaozhi и проверьте привязку здесь. Модель и голос задаются в Xiaozhi. Бесплатный доступ зависит от правил сервиса; сервер не гарантирует его бессрочно.

Подключение OpenAI
  1. Сохраните свой API-ключ OpenAI в модуле ИИ выше. Текстовая модель и её переключатель не меняют голосовую модель.
  2. Включите голос при установке сервера и настройте TLS по docs/VOICE.md. Состояние шлюза появится здесь после запуска.
  3. Создайте устройство и передайте его токен совместимому приложению Киби вместе с адресом шлюза. Ключ OpenAI остаётся на сервере.
  4. Проверьте разговор на физической Киби. Статус «Ожидает Киби» подтверждает только запущенный шлюз; доступ OpenAI и звук проверяются при разговоре.

Отзыв токена или удаление ключа завершает разговор. Голос может расходовать платный баланс OpenAI. TLS-проверка на устройстве обязательна.

ОТ ИДЕИ К ПОДКЛЮЧЕНИЮ

Соберите свою систему.

Киби Сервер — самостоятельный комплект. Устанавливается там, где удобно вам.

01

Поднимите сервер

Откройте папку server/ из исходников комплекта на GitHub. Нужен Node.js 24 для локального запуска или Docker Compose для сервера.

Локально на компьютере

Инициализация создаст личный пароль администратора и настройки. Повторный запуск сохранит существующие данные.

node scripts/init.mjs
npm start

Откройте http://127.0.0.1:4391. Пароль ищите по пути, указанному при инициализации.

На своём сервере через Docker
export KIBI_UID="$(id -u)"
export KIBI_GID="$(id -g)"
node scripts/init.mjs
docker compose up -d --build

Команды рассчитаны на обычного пользователя (UID не 0) и Node.js 24 на хосте. Если Node.js нет, используйте вариант контейнерной инициализации в START_HERE.md. Перед публичным доступом настройте домен, HTTPS и точный KIBI_PUBLIC_ORIGIN по README.md. Хранилище держите в постоянном томе; резервируйте его перед обновлениями.

02

Поручите подключение своему ИИ

Передайте ему исходники комплекта и этот промпт. Пароли, токены и ключи вводите на своём компьютере или в панели, без отправки в чат.

ГОТОВЫЙ СТАРТ

Помоги развернуть Kibi Server из папки server/ в ветке codex/kibi-server репозитория https://github.com/ezggwp1216-pixel/kibi-studio и подключить моё устройство. Сначала прочитай README.md, START_HERE.md, docs/API.md и docs/MODULES.md. Уточни, где будет работать сервер и какую задачу решает устройство. Используй Node.js 24 или Docker Compose, постоянное хранилище и HTTPS для публичного доступа. Не проси присылать секреты в чат: я введу их локально или в панели. Сохрани имеющиеся данные. Создай устройство в панели, а его одноразовый токен я передам приложению самостоятельно. Используй Bearer-токен только на серверных маршрутах устройства: POST /api/device/events, GET /api/device/messages и POST /api/device/ack. Проверь событие, очередь сообщений, подтверждение и отзыв токена. Не отправляй реальные Telegram-сообщения без моего явного запроса. Настрой текстовый ИИ через серверный модуль OpenAI и мой собственный API-ключ; характер Киби задаётся системной инструкцией. Устройство использует POST /api/device/chat; история диалога не сохраняется. Не отправляй платные запросы без моего явного согласия. Для голоса прочитай docs/VOICE.md: настрой TLS-шлюз и совместимое приложение устройства, используй gpt-realtime и серверный ключ. Сначала проверь голос с подменным транспортом; платный разговор и физическую Киби проверяй после моего согласия. Расписания пока не реализованы. Не меняй действующие серверы и прошивку без согласования. В конце покажи адрес панели, путь к резервной копии и результаты проверок.

03

Проверьте первый круг

  1. Добавьте устройство и сохраните его токен: повторно он не показывается.
  2. Пусть приложение отправит событие. Проверьте его в ленте обзора.
  3. Отправьте сообщение из раздела «Устройства». Приложение должно забрать и подтвердить его.
  4. При необходимости настройте Telegram и явно отправьте проверку.
ЗНАТЬ ЗАРАНЕЕ

Ваши данные
остаются у вас.

Сервер не нужен автономным приложениям. Он добавляет связь, внешние интеграции и место для вашей логики.

Что есть в комплекте

API, панель, события, очередь сообщений, Telegram, текстовый ИИ, голосовой TLS-шлюз и пример расширения модуля.

Что подключается отдельно

Совместимое приложение устройства и планировщик. Голосовой шлюз включается отдельно при установке. Онлайн-статус не доказывает работоспособность физической платы.
